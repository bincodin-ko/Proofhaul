# 운임근거함 — 전체 계획

운송 건별 증빙함. 안전운임 확인서를 진입점으로 하되, 제품의 본체는 **운송 한 건에 붙는 모든 증빙을 모으고 찾을 수 있게 하는 것**이다.

## 파일 구성

| 파일 | 용도 | 언제 쓰나 |
|---|---|---|
| `00-PLAN.md` | 전체 계획·일정·중단 기준 | 지금. 방향이 흔들릴 때 다시 읽기 |
| `01-SPEC.md` | 제품 사양 (화면, 데이터, 스택) | Day 1부터 |
| `02-RULES-v2026.md` | 계산 규칙 + 원문 대조 체크리스트 | Day 1 최우선 |
| `03-BUILD-PROMPT.md` | Claude Code에 붙여넣는 명령 10개 (0~7 + 4b, 6b) | 단계마다 하나씩 |
| `04-VERIFY.md` | 출시 전 최종 검증 | Day 13~14 |
| `05-SECURITY.md` | 보안 설계·위협별 요구사항·사고 대응 | Day 5 이전에 1회 통독, Day 12 점검 |

---

## 왜 이걸 만드는가 (흔들릴 때 읽을 것)

- **제도**: 안전운임제가 2026.1.1 재도입, 2028.12.31까지 3년 한시. 요율은 2026.1.30 고시로 확정돼 2026.2.1~12.31 효력
- **핵심 근거**: 요율이 연중에도 바뀐다. 2026.8.1 유가 연동으로 컨테이너 운임이 실제로 인상됐다. 즉 **7월 건과 8월 건의 계산 기준이 다르다.** 나중에 분쟁이 나면 그 시점 기준으로 재현해야 하는데 엑셀로는 안 된다
- **새 서식**: 2026년 고시에서 대기시간·험로/오지·세척/교체 확인서 표준 서식이 처음 도입됐다
- **신고 경로 실재**: 안전운임보다 낮은 운임·미지급 사례를 접수하는 안전운임신고센터가 운영 중이다

**제도는 진입 계기일 뿐 제품의 근거가 아니다.** 인수증과 부대비용 분쟁은 제도 이전에도 있었고 이후에도 남는다. 2028년 이후에도 살아남도록 범위를 "운송 건별 증빙"으로 잡았다.

---

## 아직 모르는 것 (구현과 병행해 채운다)

1. **모집단** — 안전운임 적용 대상(수출입 컨테이너·시멘트) 취급 운송사가 몇 곳인지 미확인. 공공데이터포털 `전국화물자동차운송사업자표준데이터`(차량대수 포함)로 카운트할 것
2. **정량 고통** — 증빙 없어 청구를 포기한 건수. Day 0 실험으로 간접 확인
3. **셀프서브** — 이 업종이 온라인으로 결제하는 SaaS가 있는지 미확인

## 단계

### Day 0 (반나절) — 미끼 도구

**아무에게도 연락하지 않는다.** 확인서 생성기 한 페이지만 만들어 배포한다.

- 만드는 것: 대기시간/험로·오지/세척·교체 확인서를 입력 → 서명 가능한 PDF 출력. 로그인 없음
- 올리는 곳: 물류 커뮤니티, 안전운임 관련 게시판, 운송 관련 카페
- 문구는 "도와주세요"가 아니라 **"만들어봤는데 필요하신 분 쓰세요"**
- 심는 것: 생성 횟수, 확인서 종류별 분포, 재방문 (쿠키 기준이면 충분)

### Day 0+14 — 판정

| 결과 | 행동 |
|---|---|
| 주 5건 이상 생성 | 2주 MVP 진행 |
| 같은 사람이 2회 이상 | 첫 고객 후보. 그가 남긴 흔적 우선 반영 |
| 주 2~4건 | 애매. 1주 더 본다. 그래도 안 오르면 중단 |
| 2주간 10건 미만 | **중단.** 반나절만 쓰고 끝낸다 |

중단은 실패가 아니다. 이 단계의 목적이 그거다.

### Week 1 — 뼈대 (Day 0 판정을 통과한 뒤 시작. 총 소요는 Day 0 포함 약 4주)

- Day 1~2: 고시 원문 대조 → `02-RULES-v2026.md` 확정. **이게 끝나기 전에 다른 코드를 쓰지 않는다**
  - 같은 이틀 안에 **원가를 개략 추정**한다. SMS 단가 × 예상 발송량이 객단가의 30%를 넘을 것 같으면 이 시점에 구조를 바꾼다. Day 12까지 미루면 다 만든 뒤에 알게 된다
- Day 3~4: 스키마 + 화면 1 (운송 건 등록, 엑셀 붙여넣기)
- Day 5~7: 화면 2 (토큰 링크, 모바일 서명). **시작 전 `05-SECURITY.md` 통독**

### Week 2 — 완성과 검증

- Day 8~9: PDF 생성, SMS 발송, 개인정보 처리 최소 장치
- Day 10~11: 화면 3 (누락 목록, 기간 묶음 내려받기)
- Day 12: 원가 점검 + **보안 점검** (`05-SECURITY.md` 전 항목 대조)
- Day 13~14: `04-VERIFY.md` 전체 실행

### 병행 (Week 1~2 중 아무 때나)

- 공공데이터포털에서 모집단 카운트
- Day 0 도구 사용 로그 확인

## 중단 기준 (미리 정해둔다)

하나라도 해당되면 멈추고 다시 생각한다.

- Day 0 실험 2주간 생성 10건 미만
- 고시 원문 대조 결과, 계산 규칙이 코드로 옮기기엔 예외가 너무 많음
- Day 1~2 개략 추정에서 이미 원가가 객단가의 30%를 넘고, 줄일 방법이 없음
- 모집단 카운트 결과, 도달 가능 모수 전부를 잡아도 월 1,400만원이 안 됨

## 안 만드는 것 (범위 방어)

넣고 싶어질 때마다 여기를 읽는다.

- **배차 관리** — 차플·카고링크가 이미 있다. 정면 충돌
- **대금 정산·이체** — 3일 멈추면 돈이 안 나간다. 혼자서는 위험
- **차주용 앱** — 차주는 돈을 안 낸다
- **OCR·AI 자동분류** — AI를 빼면 남는 게 없어진다
- **운임 조회 기능** — 이미 무료로 여러 곳에서 제공된다

우리가 파는 건 **"빠뜨린 증빙이 있다"를 알려주는 것** 하나다.
