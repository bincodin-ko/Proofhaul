# 최종 검증 — 출시 전 마지막 관문

각 항목을 **실제로 실행해서** 통과/실패/확인 불가로 판정한다. 코드를 읽고 추측하는 것은 검증이 아니다. 애매하면 통과가 아니라 확인 불가다.

---

## A. 정확성 — 가장 중요

숫자가 틀리면 나머지가 다 무의미하다.

- `[ ]` `02-RULES-v2026.md`의 모든 항목이 **원문 대조 완료** 상태인가. 미대조 항목이 코드에 들어가 있지 않은가
- `[ ]` 확정 안 된 규칙이 화면에서 "미지원"으로 표시되는가. 조용히 0이나 근사값을 내지 않는가
- `[ ]` 대기시간 초과 계산을 손계산과 3건 이상 대조했는가 (20FT, 40FT, 경계값 각 1건)
- `[ ]` 2026.2 기준 건과 2026.8 기준 건을 각각 만들어, **과거 건이 당시 버전으로 재계산**되는가
- `[ ]` 규칙 파일 상단에 출처 문서명과 확인 날짜 주석이 있는가
- `[ ]` 반올림·경계값 처리가 원문과 일치하는가 (2시간 정각, 2시간 1분 등)

## B. 서명 흐름 — 제품의 성립 조건

- `[ ]` 서명 링크를 **로그인 없이** 열 수 있는가
- `[ ]` 링크를 처음 받은 사람이 **설명 없이** 서명까지 마칠 수 있는가. 직접 폰으로 해보기
- `[ ]` 모바일 한 화면에 들어가는가. 가로 스크롤이 생기지 않는가
- `[ ]` 서명 후 PDF의 **한글이 깨지지 않는가.** 실제로 열어서 확인
- `[ ]` PDF에 필수 항목이 다 있는가 (운송 정보, 입력값, 서명 이미지, 서명 시각, calc_version)
- `[ ]` 만료된 링크가 안내 문구를 보여주는가. 500 에러가 아닌가

## C. 보안

전체 기준은 `05-SECURITY.md`. 아래는 출시를 막는 최소 항목이다. **전부 실제로 시도해서 확인한다.**

**토큰**
- `[ ]` CSPRNG로 생성되고 DB에는 해시로 저장되는가
- `[ ]` 토큰 문자열을 바꿔 다른 증빙·다른 회사 데이터에 닿는가
- `[ ]` 없는 토큰과 만료된 토큰의 응답이 구분되지 않는가
- `[ ]` 토큰 1개로 증빙 1건 이상이 열리지 않는가
- `[ ]` 서명 완료 후 같은 토큰으로 수정이 되지 않는가
- `[ ]` 토큰 조회에 속도 제한이 걸려 있는가

**테넌트 분리**
- `[ ]` 계정 2개로 남의 `company_id` 데이터에 접근을 시도했고 막혔는가
- `[ ]` ID가 UUID인가 (자동증가 정수가 아닌가)

**파일**
- `[ ]` 서명 이미지·첨부 사진이 URL만으로 열리지 않는가
- `[ ]` SVG·위장 확장자 업로드가 막히는가
- `[ ]` 사진의 EXIF(GPS)가 제거되는가

**기타**
- `[ ]` 비밀번호가 bcrypt/argon2로 저장되는가
- `[ ]` 내려받은 CSV에 수식 인젝션이 막혀 있는가
- `[ ]` PDF 렌더러가 원격 리소스를 불러오지 않는가
- `[ ]` `.env`가 git에 없는가. 로그에 토큰·연락처가 없는가
- `[ ]` SMS 일일 상한과 비용 알림이 있는가
- `[ ]` 킬 스위치가 동작하는가. 실제로 켜고 꺼봤는가
- `[ ]` DB 백업이 돌아가는가. **복구를 한 번 해봤는가**

## C2. 개인정보

이 서비스는 타인의 이름·연락처·서명·IP를 저장한다.

- `[ ]` 서명 화면에 수집 항목·목적·보관 기간 고지와 동의가 있는가
- `[ ]` 개인정보처리방침 페이지가 있는가
- `[ ]` 보관 기간이 정해져 있고, 지난 데이터를 지우는 방법이 있는가
- `[ ]` 서명 이미지·첨부 사진이 URL만 알면 열리지 않는가
- `[ ]` 실수로 로그에 연락처·서명 데이터가 남고 있지 않은가

## D. 비용

- `[ ]` 고객 100명 기준 월 원가 계산이 문서로 남아 있는가
- `[ ]` 원가가 객단가(월 15만원)의 **30% 이하**인가
- `[ ]` 인프라가 **월 200달러 상한** 안에 있는가. 넘는 고객 수는 몇 명부터인가
- `[ ]` SMS 발송량이 예상보다 3배가 되어도 상한 안인가

## E. 1인 운영 가능성

- `[ ]` **정지 내성**: 서비스가 3일 멈춰도 고객이 버티는가. 멈추면 고객 업무가 그날로 멈추는 지점이 있는가
- `[ ]` 고객 1명 늘 때 내 시간이 **월 30분 이하**인가. 수작업 온보딩이 필요하지 않은가
- `[ ]` 고객이 혼자 가입하고 혼자 첫 증빙을 발송할 수 있는가. 내가 전화해야 하는 단계가 없는가
- `[ ]` 장애가 났을 때 내가 알 수 있는가 (최소한의 에러 알림)

## F. 범위 방어

만드는 동안 슬쩍 들어온 게 없는지 본다.

- `[ ]` 배차 관리 기능이 들어가지 않았는가
- `[ ]` 대금 정산·이체가 들어가지 않았는가
- `[ ]` OCR·AI 자동분류가 들어가지 않았는가
- `[ ]` 운임 조회 기능이 들어가지 않았는가
- `[ ]` 대시보드·그래프가 화면 3을 잡아먹지 않았는가. 여전히 **할 일 목록**인가

## G. 사업 조건 재확인 — 사람이 직접 확인하는 항목

AI가 판정할 수 없다. 여기서 실패하면 코드 문제가 아니라 방향 문제다.

- `[ ]` **모집단 카운트**를 실제로 했는가. 도달 가능 모수가 몇 곳인가
- `[ ]` 그 모수 전부를 고객으로 잡아도 월 1,400만원이 되는가 (천장 테스트)
- `[ ]` 필요 침투율이 몇 %인가. 10%를 넘지 않는가
- `[ ]` Day 0 미끼 도구 결과가 중단 기준(2주 10건 미만)을 넘겼는가
- `[ ]` 2028년 제도 종료 후에도 남는 부분이 제품 안에 실제로 구현되어 있는가 (증빙 이력, 인수증 등 제도 무관 기능)
- `[ ]` 경쟁자가 이 기능을 한 화면으로 붙일 수 있는가. 붙이면 우리는 뭐가 남는가
