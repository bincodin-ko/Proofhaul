# 운임근거함 인프라 스택 추천

작성일: 2026-09-17 · 기준: 1인 운영, 월 상한 $200, 시급 30,000원, 환율 1,400원/$

---

## 1. 답

**인프라는 이 서비스에서 청구서의 27%밖에 안 된다. 1위는 알림톡(72%)이다.**
호스팅을 어디로 할지 오래 고민하는 것은 청구서의 4분의 1을 놓고 다투는 일이다.

**추천: Vercel Pro(서울 리전) + Supabase Pro(서울) + 알림은 앱 내 알림부터**
— 관리형 부품 2개로 끝나고, 데이터가 국내에 남고, 남는 시간을 제품에 쓸 수 있다.

| 시점 | 월 현금 | 운영 시간 | 시간 비용 | **합계** |
|---|---:|---:|---:|---:|
| 출시 직후 (고객 3) | $46 | 0.8h | $16 | **$62** |
| 고객 100 — 앱 내 알림 | $46 | 0.8h | $16 | **$62** |
| 고객 100 — 알림톡 켬 | $167 | 1.0h | $21 | **$188** |
| 고객 1,000 — 앱 내 알림 | $52 | 0.8h | $16 | **$68** |

고객 100명 시점에 **인프라(호스팅+DB+스토리지)는 월 $45로 고정**이고, 나머지는 전부 알림톡
발송량이다. 알림톡을 켜면 현금이 $167로 뛰어 상한 $200의 84%를 먹는다. 그래서 순서는
**앱 내 알림으로 출시 → 고객이 "문자로 와야 한다"고 말할 때 알림톡을 켠다**가 맞다.
`01-SPEC.md`가 이미 "SMS는 선택 기능으로 내린다"고 적어둔 것과 같은 결론이다.

한 가지 안심해도 되는 것: 알림톡을 다 켜도 **고객 1명당 월 2,340원**이다. 객단가 15만원의
**1.6%**로, 걱정했던 30% 선의 19분의 1이다. 발송량 가정이 3배 틀려도 5%다. 알림톡은
**비싸서가 아니라 상한을 걸 수 없어서** 뒤로 미루는 것이다.

셀프호스트(Hetzner + Coolify)는 현금이 $5까지 내려가지만 운영이 월 3시간(9만원)으로 늘어
합계 $69가 된다. 현금 $41을 아끼려고 시간 $43을 쓰는 셈이고, 서명 링크가 새벽에 죽으면
깨울 사람이 나뿐이다. `00-PLAN.md`의 "3일 멈춰도 버티는가"와 정면으로 부딪힌다.

## 2. 첫 주에 막힐 것

### (1) PDF 한글이 **소리 없이** 빈칸이 된다 — 그리고 파일이 56배 커진다

지금 미끼 도구가 쓰는 `pdf-lib`는 한글 폰트를 `subset: false`로 통째로 넣고 있다.
서브셋을 켜면 글자가 빈칸이 되기 때문인데, **텍스트 추출은 멀쩡해서 PDF를 눈으로 열기
전까지 정상으로 보인다.** 원인은 `@pdf-lib/fontkit`의 TrueType 서브셋터가 합성
글리프(composite glyph)를 옮기지 못하는 것이고, 나눔고딕은 **글리프 13,297개 중 8,825개
(66%)가 합성**이다. 합성 글리프를 미리 펴 봐도 고쳐지지 않는다(직접 해봤다).

`pdfkit`은 상류 `fontkit`을 쓰고 이 문제가 없다. 같은 문장으로 직접 재봤다.

| 방법 | PDF 크기 | 한글 |
|---|---:|---|
| pdf-lib, subset 켬 | 12 KB | **깨짐** |
| pdf-lib, subset 끔 (현재) | 764 KB | 정상 |
| **pdfkit** | **13.5 KB** | **정상** |

```js
// 서버에서 확인서 PDF 만들기 — 폰트 등록이 전부다.
// 나눔고딕 TTF를 레포에 두고 경로로 등록하면 pdfkit이 알아서 필요한 글자만 넣는다.
import PDFDocument from "pdfkit";

const doc = new PDFDocument({ size: "A4", margin: 48 });
const chunks = [];
doc.on("data", (c) => chunks.push(c));
const done = new Promise((r) => doc.on("end", r));

// 핵심: registerFont 에 TTF 경로를 주고, 쓰기 전에 font()로 고른다.
// 이걸 빼먹고 기본 폰트(Helvetica)로 한글을 쓰면 전부 빈칸이 된다.
doc.registerFont("ng", "fonts/NanumGothic-Regular.ttf");
doc.font("ng").fontSize(11).text("운송 건 정보 · 뷁 쀍 똠", 48, 100);

doc.end();
await done;
const pdf = Buffer.concat(chunks); // ≈ 13KB
```

**반드시 렌더링해서 눈으로 확인한다.** 텍스트 추출만으로는 이 버그를 못 잡는다.
희귀 음절(`뷁 쀍 똠 짊 옰 휭`)을 테스트 문자열에 섞어두면 드문 글자까지 걸러진다.

### (2) 서명 이미지·첨부 사진을 서버로 통과시키면 안 된다

지금 `web/lib/storage.ts`는 파일을 서버 함수가 받아서 디스크에 쓴다. 서버리스에서는
파일이 함수를 지나가는 동안 실행 시간과 메모리를 먹고, 요청 본문 한도에도 걸린다.
**브라우저가 스토리지로 직접 올리게 하고, 서버는 서명된 URL만 발급**해야 한다.

특히 A5의 사진 첨부는 현장 사진이라 몇 MB씩 된다. 이걸 함수로 받으면 비용도 실패율도
같이 올라간다. 업로드 후 서버가 EXIF 제거·재인코딩을 하는 구조로 간다.

### (3) 항만 지하와 산간에서 서명 제출이 실패한다

서명은 항만 게이트, 물류센터 지하, 산간 오지에서 일어난다. 제출 요청 하나가 네트워크로
실패하면 차주는 이미 차를 몰고 떠났고 **다시 부를 수 없다.** 서명은 되돌릴 수 없는
행위라 재시도가 제품의 성립 조건이다.

서명 데이터(입력값 + 서명 PNG)를 제출 직전에 `localStorage`에 넣고, 성공하면 지운다.
실패하면 화면에 "다시 보내기"를 띄우고 복귀 시 자동 재시도한다. 서버는 같은 토큰으로
두 번 들어와도 한 번만 반영되므로(`evidence_sign`의 `WHERE status='REQUESTED'`) 중복
제출은 이미 안전하다.

## 3. 첫 주에 할 일

1. **Vercel Pro 결제 + 사용량 알림을 먼저 건다.** Hobby는 상업 사용이 금지라 첫 유료 고객
   시점에 필요하고, 알림을 먼저 걸어야 청구서가 놀라지 않는다.
2. **Supabase 프로젝트를 서울 리전으로 만들고 Pro로 올린다.** 무료 티어는 7일 미사용 시
   일시정지가 있어 데이터 층을 올릴 곳이 아니다.
3. **A5의 PDF를 `pdfkit`으로 확정**하고, 만든 PDF를 실제로 렌더링해 한글을 눈으로 확인한다.
4. **알림은 앱 내 알림으로 출시한다.** 알림톡 발신프로필·템플릿 심사는 지금 신청만 걸어두고,
   고객이 요구할 때 켠다.
5. **백업을 한 번 복구해 본다.** 복구해 본 적 없는 백업은 백업이 아니다.
