## 1. 답

**지금은 0원이다.** 고객이 0명이고 2주 뒤 중단할 수도 있는데 월 6만원짜리 계정을 여는 것은
틀린 순서다. 돈은 **첫 고객이 돈을 내기 시작할 때** 쓰기 시작한다.

| 단계 | 언제 | 무엇을 | 월 현금 | 운영 시간 | **실질 합계** |
|---|---|---|---:|---:|---:|
| **0. 지금** | 고객 0, 미끼 관찰 중 | 미끼만 Vercel Hobby. 본체는 로컬 | **0원** | 0h | **0원** |
| **1. 첫 고객~20명** | 월 매출 15만~300만 | VPS 1대에 전부 + R2 백업 + 도메인 | **1.0만원** | 1h | **4.0만원** |
| **2. 고객 20명~** | 월 매출 300만~ | Vercel Pro + Supabase Pro(서울) | **6.5만원** | 0.8h | **8.9만원** |
| (알림톡을 켜면) | 고객 100 기준 | 위에 발송량만큼 | +17만원 | +0.2h | +17.6만원 |

**인프라가 매출보다 먼저 나가는 구간이 없다.** 고객 1명일 때 인프라는 매출의 7%,
고객 20명이면 0.3%다. 2단계로 넘어가는 시점(고객 20명)에는 매출이 300만원이라
6.5만원이 2%밖에 안 된다.

### 왜 처음부터 관리형이 아닌가

처음엔 관리형(Vercel Pro + Supabase Pro)을 바로 권했는데, **고객 100명 시점을 최적화하고
지금을 놓친 판단이었다.** 두 가지를 잘못 봤다.

1. **운영 시간을 규모와 무관한 상수로 잡았다.** VPS 운영 월 3시간은 트래픽이 있을 때의
   숫자다. 고객 3명 구간에서는 백업 확인과 가끔의 패치뿐이라 **월 1시간**이다.
   이 상수 하나 때문에 셀프호스트가 실제보다 $43 비싸 보였다.
2. **"출시 직후"를 고객이 이미 있는 상태로 가정했다.** 실제 현재 상태는 고객 0명이고,
   `00-PLAN.md`의 중단 기준(2주 10건 미만)에 걸리면 제품 자체가 없어진다.
   그 구간에 월 6만원은 검증 비용이 아니라 매몰 비용이다.

### 왜 1단계에서 VPS인가 — 그리고 왜 2단계에서 떠나는가

지금 코드에는 **락인이 없다.** DB는 순수 Postgres, 파일은 어댑터 하나, 앱은 Next.js다.
반대로 Supabase로 시작하면 Storage·Auth API에 붙어서 나가기 어려워진다.
**싼 쪽이 이전도 쉬운 드문 경우**라 순서를 뒤집을 이유가 없다.

떠나는 기준은 돈이 아니라 시간이다. 고객이 20~30명이 되면 VPS 운영이 월 2~3시간으로
늘고, 그 시간은 영업과 제품에 써야 하는 시간이다. 그때는 6.5만원이 매출의 2%라 안 아프다.

부품은 1단계 2개(VPS, R2), 2단계 2개(Vercel, Supabase)로 양쪽 다 최소다.

### 알림톡은 비싸서가 아니라 상한을 못 걸어서 미룬다

고객 100명 시점에 알림톡을 다 켜면 월 17만원으로 **청구서의 72%**가 된다. 인프라
(호스팅+DB+스토리지)는 6.5만원으로 27%에 불과하다.

그런데 고객 1명당으로 보면 **월 2,340원, 객단가 15만원의 1.6%**다. 걱정했던 30% 선의
19분의 1이라 비용 자체는 문제가 아니다. 문제는 **알림톡에 지출 상한을 걸 수 없다**는 것이다.
발송량이 그대로 청구서가 된다. 그래서 순서는 **앱 내 알림으로 출시 → 고객이 "문자로 와야
한다"고 말할 때 회사당 일일 상한을 먼저 넣고 켠다**가 맞다. `01-SPEC.md`가 이미
"SMS는 선택 기능으로 내린다"고 적어둔 것과 같은 결론이다.

## 2. 첫 주에 막힐 것

### (1) PDF 한글이 **소리 없이** 빈칸이 된다 — 그리고 파일이 56배 커진다

지금 미끼 도구가 쓰는 `pdf-lib`는 한글 폰트를 `subset: false`로 통째로 넣고 있다.
서브셋을 켜면 글자가 빈칸이 되기 때문인데, **텍스트 추출은 멀쩡해서 PDF를 눈으로 열기
전까지 정상으로 보인다.** 원인은 `@pdf-lib/fontkit`의 TrueType 서브셋터가 합성
글리프(composite glyph)를 옮기지 못하는 것이고, 나눔고딕은 **글리프 13,297개 중 8,825개
(66%)가 합성**이다. 합성 글리프를 미리 펴 봐도 고쳐지지 않는다(직접 해봤다).

`pdfkit`은 상류 `fontkit`을 쓰고 이 문제가 없다. 같은 문장으로 직접 재봤다.

| 방법 | PDF 크기 | 한글 |
|---|---:|---|
| pdf-lib, subset 켬 | 12 KB | **깨짐** |
| pdf-lib, subset 끔 (현재) | 764 KB | 정상 |
| **pdfkit** | **13.5 KB** | **정상** |

```js
// 서버에서 확인서 PDF 만들기 — 폰트 등록이 전부다.
// 나눔고딕 TTF를 레포에 두고 경로로 등록하면 pdfkit이 알아서 필요한 글자만 넣는다.
import PDFDocument from "pdfkit";

const doc = new PDFDocument({ size: "A4", margin: 48 });
const chunks = [];
doc.on("data", (c) => chunks.push(c));
const done = new Promise((r) => doc.on("end", r));

// 핵심: registerFont 에 TTF 경로를 주고, 쓰기 전에 font()로 고른다.
// 이걸 빼먹고 기본 폰트(Helvetica)로 한글을 쓰면 전부 빈칸이 된다.
doc.registerFont("ng", "fonts/NanumGothic-Regular.ttf");
doc.font("ng").fontSize(11).text("운송 건 정보 · 뷁 쀍 똠", 48, 100);

doc.end();
await done;
const pdf = Buffer.concat(chunks); // ≈ 13KB
```

**반드시 렌더링해서 눈으로 확인한다.** 텍스트 추출만으로는 이 버그를 못 잡는다.
희귀 음절(`뷁 쀍 똠 짊 옰 휭`)을 테스트 문자열에 섞어두면 드문 글자까지 걸러진다.

### (2) 파일 어댑터를 지금 S3 호환으로 맞춰둔다

1단계(VPS)에서는 지금처럼 로컬 디스크에 써도 된다. 문제는 **2단계로 옮길 때**다.
`web/lib/storage.ts`가 파일을 서버가 직접 받아 쓰는 구조인데, 서버리스에서는 파일이
함수를 지나가는 동안 실행 시간과 메모리를 먹고 요청 본문 한도에도 걸린다.

A5에서 어댑터 인터페이스를 **S3 호환(`putObject` + 서명된 URL 발급)** 모양으로 맞춰두면,
1단계에서는 로컬 구현을 쓰고 2단계에서 구현만 바꾸면 된다. 지금 어댑터 모양을 잘못 잡으면
나중에 호출부를 전부 고쳐야 한다.

특히 A5의 사진 첨부는 현장 사진이라 몇 MB씩 된다. 2단계에서는 브라우저가 스토리지로
직접 올리고 서버는 서명된 URL만 발급해야 한다.

### (3) 항만 지하와 산간에서 서명 제출이 실패한다

서명은 항만 게이트, 물류센터 지하, 산간 오지에서 일어난다. 제출 요청 하나가 네트워크로
실패하면 차주는 이미 차를 몰고 떠났고 **다시 부를 수 없다.** 서명은 되돌릴 수 없는
행위라 재시도가 제품의 성립 조건이다.

서명 데이터(입력값 + 서명 PNG)를 제출 직전에 `localStorage`에 넣고, 성공하면 지운다.
실패하면 화면에 "다시 보내기"를 띄우고 복귀 시 자동 재시도한다. 서버는 같은 토큰으로
두 번 들어와도 한 번만 반영되므로(`evidence_sign`의 `WHERE status='REQUESTED'`) 중복
제출은 이미 안전하다.

## 3. 첫 주에 할 일

**이번 주에 쓸 돈은 도메인값 말고 없다.**

1. **미끼 도구를 Vercel Hobby로 올린다.** Root Directory를 `bait`로. 무료 도구라
   Hobby로 충분하다. 2주 관찰 시계를 오늘 시작하는 것이 이번 주의 전부다.
2. **본체는 배포하지 않는다.** 첫 고객이 생기기 전까지 로컬에서 개발한다.
   Vercel Pro도 Supabase Pro도 지금 열 이유가 없다.
3. **A5의 PDF를 `pdfkit`으로 확정**하고, 만든 PDF를 실제로 렌더링해 한글을 눈으로 확인한다.
4. **파일 어댑터를 S3 호환 모양으로 잡는다.** 구현은 로컬 디스크로 두고 모양만 맞춘다.
5. **알림은 앱 내 알림으로 만든다.** 알림톡 발신프로필·템플릿 심사는 신청만 걸어둔다.

첫 고객이 생기면 그때 하는 일(반나절): 서울 VPS 1대, 도메인, 매일 `pg_dump` + 파일을
R2로 올리는 크론, 그리고 **복구를 한 번 해본다.** 복구해 본 적 없는 백업은 백업이 아니다.
