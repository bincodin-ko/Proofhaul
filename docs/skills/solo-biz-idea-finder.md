# 소규모 개발팀 사업 아이템 발굴

## 이 스킬의 목적

아이디어를 "많이" 내는 게 아니라, **이미 누군가 돈을 지불하고 있는 문제**를 찾아 혼자서 2주 안에 손댈 수 있는 크기로 잘라내는 것이다.
브레인스토밍 결과물이 아니라, 내일 전화를 걸 대상이 명확한 후보를 만든다.

## 고정 전제 (매번 다시 묻지 말 것)

- 팀: 1인 개발, 완전 부트스트랩 (외부 투자 없음). 개발·영업·고객응대·운영을 전부 한 사람이 한다
- 인프라 예산: 월 200달러 상한 (엄격)
- 목표: 0 → 월 매출 1만 달러
- MVP 규모: 2주 안에 만들 수 있을 것
- 시장 우선순위: 한국 먼저, 그다음 글로벌
- 결제: 국내 토스페이먼츠 / 해외 MoR
- 기간 목표: 1년 안에 수익화
- 고정비가 거의 없으므로 월 매출 1만 달러면 사업으로 성립한다

**정지 내성** — 1인이라 추가되는 단 하나의 제약.
> 내 제품이 3일 멈추면 고객에게 무슨 일이 생기는가?

- 아무 일도 안 생긴다 / 고객이 잠시 예전 방식으로 돌아간다 → 안전
- 고객의 그날 업무가 멈추거나 돈·법적 문제가 생긴다 → **혼자서는 위험**. 결제 중계, 실시간 관제, 마감이 걸린 신고 대행 등이 여기 해당한다

혼자이므로 자는 동안, 아플 때, 여행 중일 때 아무도 대신 받아주지 않는다. 이 하나만 통과하면 나머지는 기존 조건(C2 셀프서브, C5 확장성)이 이미 잡아준다.

이 전제를 깨는 아이디어는 아무리 좋아 보여도 제시하지 않는다. 예산 초과, 6주짜리 MVP, 미국 전용 아이디어는 그 자리에서 버린다.

## 현실을 보는 법 — 문서가 아니라 구조를 본다

**자료를 아무리 많이 읽어도 구조를 안 그리면 못 본다.**

사실은 다 읽었는데 그 사실이 무엇을 뜻하는지 몇 시간 뒤에야 아는 일이 자주 일어난다.
읽은 문장을 **그림으로 옮기는 단계**가 없기 때문이다. 아래 여섯 개를 **아이디어마다
실제로 써서** 만든다. 머릿속으로 하면 안 한 것과 같다.

*(아래 예시는 한 프로젝트를 중단시킨 실제 사례다. 여섯 개 중 넷을 안 그려서 중단이
며칠 늦었다.)*

### A. 돈·서류·권한의 흐름도

화살표로 그린다. 짧아도 된다.

- **누가 누구에게 돈을 주나**
- **누가 먼저 손해를 보나** — 선지급·후청구 구조가 있으면 반드시 표시한다
- **누가 서류에 서명할 권한이 있나**
- **우리 제품은 어느 화살표에 붙나**

> **고객은 가장 시끄러운 칸이 아니라 손해를 실제로 떠안는 칸이다.**

*실패 예: 고시에 "대기료는 운수사업자가 차주에게 우선 지급한 뒤 원인제공자에게
청구한다"는 문장이 있었다. 읽었고, 문서에 옮겨 적기까지 했다. 그런데 **그 한 문장이
"고객이 차주가 아니라 운송사"라는 뜻이라는 걸** 몇 시간 뒤에야 알았다.*

### B. 사람 지도 — 누가 어느 방에 있나

역할마다 한 줄씩. **"이 사람들은 어디에 모여 있나."**

| 역할 | 손해를 보나 | 어디 모여 있나 |
|---|---|---|

- 관찰 채널은 **돈을 내는 역할이 있는 방**으로 고른다
- 그 역할이 모이는 방이 **없으면** 그것 자체가 큰 리스크다. 사장님은 대개 온라인에 없다

*실패 예: 손해를 보는 쪽은 운송사인데, 조사하러 간 곳은 차주 카페였다.*

### C. 이미 어떻게 때우고 있나

문제가 진짜면 사람들은 **이미 무언가로 때우고 있다.** 그게 충분히 좋으면 끝이다.

| 지금 쓰는 방법 | 왜 충분한가 | 왜 부족한가 |
|---|---|---|

- 후보에 **엑셀 · 카톡 · 전화 · 그냥 포기**를 반드시 넣는다
- **"어찌저찌 되고 있다"는 답이 나오면 거기서 끝낸다.** 비타민은 팔리지 않는다
- 이 표를 **추측으로 채우면 안 된다.** 당사자에게 듣거나 그들이 쓴 글에서 옮긴다

### D. 2차 효과 — "그래서 어떻게 되나"를 세 번 묻는다

```
변화  →  1차 효과  →  2차 효과  →  우리 수요는 늘어나나 줄어드나
```

한 번만 묻고 멈추는 것이 이 스킬에서 가장 비싼 실수다.

*실패 예: "화주에게 서명 의무가 생겼다" → 1차 "법적 근거가 생겼다, 우리에게 유리하다"
에서 멈췄다. 2차는 반대였다 — **의무가 생기면 서명이 알아서 이뤄지고, 서명을 받아내는
도구는 필요 없어진다.** 가장 큰 자산이라 믿었던 것이 사실은 가장 큰 위협이었다.*

규제를 계기로 삼은 아이디어는 특히 그렇다. **규제는 시장을 열기도 하지만, 그 규제가
문제를 직접 해결해 버리면 열기 전에 닫는다.**

### E. 반대 증거를 먼저 배정한다

가설을 적은 **그 자리에서** 한 줄 더 쓴다.

> **이 가설이 틀렸다면 무엇이 보일까?**

그리고 그걸 **찾으러 간다.** 지지 증거만 모으는 조사는 조사가 아니다.

증거는 지지·반박을 **같은 표에** 놓고 각각 강도를 매긴다.

| 강도 | 무엇인가 |
|---|---|
| **강** | 당사자의 직접 관찰·직접 발언 |
| 중 | 통계, 제도 원문 |
| 약 | 기사, 2차 자료 |
| 매우 약 | 한 사람의 일화, 추론 |

**직접 관찰 하나가 약한 증거 다섯 개를 이긴다.** 반대 방향이어도 마찬가지다.

### F. 숫자의 출생기록

**모든 숫자 옆에 어디서 왔는지 등급을 적는다.**

`원문` · `통계` · `기사` · `관계자 말` · **`내가 가정함`**

- **`내가 가정함`인 숫자 위에 다른 계산을 얹지 않는다.** 얹었으면 결론에 그 사실을 적는다
- 몇 번 굴린 숫자는 출처를 잃고 전제처럼 굳는다. 그게 제일 위험하다

*실패 예 둘. 객단가 "월 3만원"은 인프라 비용을 따질 때 내가 임의로 깐 숫자인데
나중엔 시장 크기 판정의 전제가 되어 있었다. "대기 3~4시간"은 2022년 기사에 실린
차주 한 명의 말인데 손실액 계산 전체의 바닥이 되어 있었다.*

## 절대 필터 (통과 못 하면 즉시 폐기)

### 1. 돈 필터
**이미 대행업체·알바·외주·직원 시간으로 지불되고 있는 비용을 뺏어오는 것만 유효하다.**
"있으면 좋겠다", "효율이 올라간다"는 무효. 지금 그 일에 월 얼마가 나가는지 말할 수 없으면 아이디어가 아니다.

### 2. 2023년 테스트
**웹 검색 없이 2023년에도 떠올릴 수 있었던 아이디어는 버린다.**
2026년에만 존재하는 문제(새 규제, 새 API 정책 변경, 새 플랫폼 등장, 최근 산업 구조 변화)여야 한다. 최신 정보 확인 없이 아이디어를 생성하지 말 것 — 반드시 웹 검색으로 "최근에 생긴 문제"임을 확인한다.

### 3. 거시 문제 배제
모두가 아는 큰 문제("의료 인력 부족", "AI 도입 어려움")는 기회가 아니다.
큰 문제 **안쪽의**, 대기업이 움직이기엔 너무 작은 틈새를 고른다.

### 4. 제외 카테고리 (이미 검토 후 탈락한 것들 — 다시 꺼내지 말 것)
- 컴플라이언스 대시보드 / 규제 체크리스트 일반론
- LLM 관측·평가·프롬프트 회귀테스트
- GEO/AEO 모니터링
- AI 회의록, 챗봇 빌더, 이력서 스크리닝, 인보이스 OCR
- 대시보드 통합류
- SOC2 자동화, 보안 설문 자동응답

### 5. 실행 불가 조건 (하나라도 걸리면 폐기)
- 통신사·카드사·보험사와의 사전 제휴가 필수
- HIPAA·의료데이터·보험사 포털 자동화
- 금융 라이선스, PG, 전자금융업 등록 필요
- 2개월 넘는 엔터프라이즈 콜드세일즈가 필수
- 수개월짜리 수작업 데이터셋 구축이 선행되어야 함
- 양면 마켓플레이스 (공급·수요를 동시에 모아야 하는 것)

### 5-1. 아픔의 증거 관문 (코드보다 먼저)

**그 문제를 겪는 사람이 쓴 글을 직접 찾아 인용하지 못했으면, 이 아이디어는 아직 아이디어가 아니다.**

#### 통과 조건

커뮤니티·카페·앱 리뷰·게시판에서 **그 문제를 말하는 글을 최소 5개** 찾아 원문 문장을 그대로 옮긴다. 요약이 아니라 **인용**이다. 못 찾았으면 "못 찾았다"고 적고 아이디어를 폐기 후보로 내린다.

#### 나오는 답을 세 갈래로 가른다

| 나온 말 | 뜻 | 판정 |
|---|---|---|
| "이것 때문에 돈을 잃었다", "이거 해결해주는 거 없나요" | **진통제** | 통과 |
| "짜증난다", "불편하다" — 그런데 **어찌저찌 해결하고 있다** | **비타민** | **폐기.** 비타민은 팔리지 않는다 |
| 아무도 그 얘기를 안 한다 | 문제가 없거나, **채널을 잘못 골랐다** | 아래 참조 |

**"어찌저찌 해결하고 있다"가 나오면 거기서 끝낸다.** 이미 충분히 풀리고 있는 문제를 더 잘 푸는 제품은 팔리지 않는다.

#### 채널을 잘못 고르는 흔한 함정

**고통을 느끼는 사람 · 돈을 내는 사람 · 우리가 들여다본 채널이 서로 다를 수 있다.** 비용이 누구에게 청구되는지를 먼저 확인하고, **돈을 내는 쪽이 모이는 곳**을 본다. 현장 종사자 커뮤니티에 사장님은 없다.

아무 말도 안 나왔을 때는 둘 중 무엇인지 **반드시 구분하고 넘어간다.** 구분 못 한 채 "아직 아무도 모르는 문제"라고 결론 내리는 것이 이 관문의 실패다.

#### 규제·제도를 계기로 삼은 아이디어라면 하나 더

**그 규제가 문제를 직접 해결해 버리는가?**

새 법이 의무를 만들고 서식을 정하고 벌칙을 붙이면, 그 의무를 대신 챙겨주는 제품의 필요가 **줄어든다.** 규제는 시장을 열기도 하지만 열기 전에 닫기도 한다. "법이 생겨서 사람들이 이걸 필요로 할 것이다"는 추론이지 관찰이 아니다.

**새 법이 생겼다 ≠ 사람들이 괴롭다.** 계기와 수요를 구분하지 못하는 것이 규제 기반 아이디어의 첫 번째 사망 원인이다.

### 6. 경쟁 현실성 필터
아이디어를 내기 전에 **이미 그 자리에 누가 앉아 있는지** 반드시 검색해서 확인한다. 기억에 의존하지 말 것. 국내 서비스, 해외 서비스, 오픈소스, 엑셀 템플릿, **그리고 앱스토어**까지 찾는다.

#### 앱스토어는 따로, 반드시 본다

웹 검색만으로 경쟁자를 찾았다면 그 조사는 절반짜리다. **현장 직군**을 상대하는 제품 — 화물·건설·미용·수리·배달·농업·정비·간병 같은 곳 — 은 웹에 흔적이 거의 없다. 블로그도 보도자료도 투자 소식도 없이 **앱스토어에만 존재하고 설치 수는 수만 건**인 앱이 흔하다. 이런 앱은 웹 검색 결과 상위에 절대 안 올라온다. 그래서 따로 찾지 않으면 "경쟁자가 없다"는 결론이 그냥 틀린 결론이 된다.

- **Google Play와 App Store를 각각** 본다. 한쪽에만 있는 앱이 많다
- 검색어를 **제품 개념이 아니라 현장 용어**로 넣는다. "증빙 관리"로는 안 나오고 "인수증", "배차", "콜화물", "운송료", "미수", "장부"로 나온다. Phase 2에서 찾은 현업 용어를 그대로 쓴다
- 상위 앱마다 **설명 전문 · 최근 업데이트 날짜 · 설치 수 · 최신 리뷰 20개**를 읽는다. 업데이트가 2년 넘게 멈춘 앱은 경쟁자가 아니라 **빈자리의 증거**다. 리뷰는 Phase 2 "바닥의 소리" 자료로 그대로 쓴다
- 우리가 만들려는 기능이 기존 앱의 **메뉴 하나로 이미 들어 있으면** "한 화면 흡수"에 해당한다. 폐기 대상이다
- 찾은 앱 이름을 경쟁 지형 표에 **그대로 적는다.** 못 찾았으면 "Play·App Store에서 `인수증`, `배차`로 검색했으나 없음"처럼 **검색어까지 적는다.** 검색어를 못 적으면 안 본 것이다

접속이 막혀 직접 못 봤으면 **"확인 못 함 — 사용자 확인 필요"라고 쓰고 무엇을 확인해야 하는지 지목한다.** 못 본 것을 "없다"로 적지 않는다.

다음 중 하나라도 해당되면 폐기한다.

- **한 화면 흡수**: 이미 자리 잡은 서비스가 메뉴 하나만 추가하면 끝나는 기능이다
- **끼워팔기 대상**: 대기업이 이미 파는 제품의 무료 부가기능으로 붙을 수밖에 없다 (네이버·카카오·토스·더존·영림원 등의 기본 기능에 흡수되는가?)
- **정면 대결**: 같은 문제를 같은 방식으로 푸는 서비스가 이미 있고, 우리 차별점이 "더 싸게" 또는 "UI가 더 좋게"뿐이다

살아남으려면 **왜 기존 강자가 이걸 안 하는지**를 한 문장으로 답할 수 있어야 한다. 좋은 답: 고객 규모가 작아 그들의 영업조직이 안 움직인다 / 그들의 기존 고객과 이해가 충돌한다 / 그들 제품 구조상 끼워넣기 어렵다. 나쁜 답: 아직 못 봤을 것이다.

### 7. 문제 적중 필터 (가장 자주 실패하는 지점)

**증상 하나를 푸는 것을 문제를 푸는 것으로 착각하지 말 것.**

아이디어를 쓰기 전에, 고른 문제를 반드시 3층으로 쪼갠다.

1. **인지층** — 사용자가 무엇이 문제인지조차 모른다
2. **진단층** — 문제가 있는 건 아는데, 내 상황에 무엇이 해당되는지 모른다
3. **해결층** — 뭘 해야 하는지 알아도 실행할 능력·시간이 없다

그다음 아이디어가 **어느 층의 몇 퍼센트를 덮는지** 표시한다.

**예시 (나쁨 → 좋음):**
문제: "바이브코딩으로 만든 서비스의 보안"
- 나쁜 아이디어: 여러 계정으로 가상 실행해 개인정보 노출을 점검하는 도구
  → 진단층의 **증상 하나**만 덮음. 초보자는 애초에 어떤 보안 문제가 존재하는지(인지층), 내 코드의 무엇이 위험한지(진단층 전체), 어떻게 고치는지(해결층)를 전혀 모르는데 그게 다 비어 있다.
- 좋은 방향: 내 코드·서비스를 읽고 **"당신에게 해당되는 위험은 이 4개"를 알려주고(인지+진단), 각각을 고친 코드까지 내놓는 것(해결)**. 개인정보 점검은 그 안의 한 항목이 된다.

판정 규칙:
- 한 층의 한 증상만 덮는다 → **폐기**하거나, 그 증상을 포함하는 상위 문제로 **확대해서 다시 쓴다**
- 세 층 중 두 층 이상을 덮어야 제시 가능
- 단, 세 층을 다 덮느라 2주 MVP를 넘기면 안 된다. 이때는 **층을 좁히지 말고 범위를 좁힌다** — "모든 보안"이 아니라 "결제 붙인 개인 서비스의 보안"처럼 대상을 좁혀서 세 층을 다 덮는다.

### 8. 다양성 쿼터 (최종 제시 4개에 적용) — 경로에 따라 다르게 적용한다

Phase 2에서 시장을 하나로 좁혀 놓고 "서로 다른 산업 4개"를 요구하면 물리적으로 불가능하다. 그러므로 쿼터는 **어떤 경로로 왔는지**에 따라 달라진다.

**넓게 훑은 경우** (Phase 1-A에서 여러 산업을 후보로 두고 왔거나, 사용자가 산업을 좁히지 않은 경우)
- 4개가 서로 다른 산업일 것
- 개발자 도구는 **최대 1개**
- **최소 2개**는 '지루한 산업' — 폐기물, 장례, 검침, 창고, 축산, 소규모 제조, 협회, 학원, 공공조달 등
- **최소 1개**는 한국 구조적 특수성 — 홈택스 API 부재, 알림톡 대행사, 세금계산서, 오픈마켓 API 파편화, 정부 포털 등

**한 시장을 깊게 판 경우** (Phase 2에서 시장 1~2개로 좁힌 경우) — 산업 분산 대신 **고객군 분산**을 본다
- 4개가 **서로 다른 고객군**일 것. 같은 문제라도 돈을 내는 주체가 달라야 한다 (예: 운수사업자 / 화주 / 주선사 / 협회)
- 개발자 도구는 **최대 1개**
- 한국 특수성 조건은 그대로 적용한다. 좁힌 시장이 이미 한국 제도 기반이면 자동 충족으로 본다
- 지루한 산업 조건은 **면제한다.** 시장을 이미 골랐으므로 이 단계에서 다시 요구할 것이 아니다

**어느 쪽이든**: 쿼터를 맞추려고 필터를 통과 못 한 것을 끼워 넣지 않는다. 3개만 살아남으면 3개를 내고, 4번째 자리가 왜 비었는지 한 줄로 밝힌다.

### 9. 문제 해상도 테스트 (통과 못 하면 아이디어가 아니다)

**"건설업의 AI 활용이 어렵다"는 문제가 아니라 주제다.** 주제를 문제로 착각하면 그 아래 모든 계산이 무의미해진다. 아래 다섯을 답할 수 없으면 아이디어로 쓰지 않는다.

**(1) 실패 장면 하나**
누가, 어떤 도구로, 무엇을 하려다가, 정확히 어느 순간 막히는가. 30초짜리 장면으로 재연할 수 있을 만큼 구체적이어야 한다.
- 나쁨: "현장 소장이 AI를 잘 못 쓴다"
- 좋음: "현장 소장이 도면 PDF를 올리고 물량을 뽑으려는데, 회사 표준 도면 기호를 못 읽어서 숫자가 틀리게 나오고, 어디가 틀렸는지 표시가 안 되니 결국 처음부터 손으로 센다"

**(2) 실패 유형을 최소 3개로 쪼갤 것**
하나의 주제 안에는 서로 다른 실패가 여러 개 섞여 있다. 쪼갠 뒤 **그중 무엇을 고르는지** 명시한다.
건설업 AI 예시:
- ① 결과물 자체가 엉터리 — 말이 안 되는 설계·물량을 내놓는다
- ② 결과는 그럴듯한데 법규·구조 기준·지자체 조례를 모른다
- ③ 쓸 줄을 모른다 — 무엇을 시킬 수 있는지, 어떻게 물어야 하는지 모른다
- ④ 우리 회사 데이터를 못 넣어서 일반론만 나온다 (도면 양식, 단가표, 협력사 정보)
- ⑤ 결과를 검증할 방법이 없어서 못 믿고 결국 안 쓴다
- ⑥ 책임 문제 — 틀렸을 때 누가 책임지나가 정리 안 돼서 도입을 못 한다

**이 다섯 개는 완전히 다른 제품이 된다.** 하나를 고르지 않고 "건설 AI 도구"를 만들면 아무것도 못 푼다.

**(3) 그래서 지금 그들이 실제로 하는 행동**
포기했나, 우회했나, 사람을 더 썼나, 몰래 쓰고 있나. 행동이 없으면 고통도 없는 것이다.

**(4) 업계 언어로 말할 수 있는가**
그 바닥 사람이 쓰는 단어로 문제를 설명해 본다. 일반 용어("효율", "생산성", "워크플로우")로만 쓰였다면 아직 그 문제를 모르는 것이다. 현업 용어를 못 찾았으면 Phase 2 조사가 부족한 것이다.

**(5) 반박당할 수 있는 서술인가**
현업에게 보여줬을 때 **"아니 그거 아닌데요"라고 틀렸다고 말할 수 있을 만큼** 구체적이어야 한다. 누구도 반박할 수 없게 뭉뚱그려진 문제 서술은 검증이 불가능하므로 실패다.

**판정**: (2)에서 실패 유형을 3개 이상 못 쪼개거나 (1)의 장면을 못 쓰면, 아이디어를 쓰지 말고 **Phase 2로 되돌아가 조사를 더 한다.** 이 상태로 아이디어를 밀어붙이는 것이 이 스킬의 두 번째로 큰 실패다.

## 지속 조건 7종 (폐기가 아니라 점수로 다룬다)

절대 필터와 달리, 여기 걸린다고 바로 버리지 않는다. **걸린 지점과 우회안을 함께 적고, 순위에 반영한다.** 필터를 계속 늘리면 살아남는 아이디어가 0개가 되어 오히려 쓸모가 없어지기 때문이다. 단, "치명"으로 표시된 조건은 예외로 폐기한다.

### C1. 반복성 — 구독이 붙는 문제인가
문제가 얼마나 자주 발생하는가: 매일 / 매주 / 매월 / 분기 / 연 1회.
연 1회짜리(연말정산, 사업자 등록, 인증 갱신)는 아무리 아파도 월 구독이 안 붙고, "월 얼마 × 몇 명" 계산 자체가 성립하지 않는다.
- 우회안: 폐기하지 말고 **그 사람이 매달 반복하는 인접 업무로 범위를 넓힌다**. 연 1회 신고가 아니라, 그 신고를 위해 매달 쌓아야 하는 기록 쪽으로.

### C2. 셀프서브 가능성 — 카드로 결제할 사람들인가
지루한 산업 쿼터와 정면으로 부딪히는 조건이다. 폐기물·장례·검침 업체는 문제는 확실하지만, 그 사장이 온라인으로 SaaS를 결제한 적이 없으면 전화 영업이 필요하고 1인 개발자는 감당하지 못한다.
- **검색으로 확인할 것**: 이 업종이 이미 온라인 결제로 쓰고 있는 SaaS가 하나라도 있는가. 있으면 통과.
- 우회안: 산업은 유지하되 **타겟을 한 칸 옮긴다** — 그 업종을 상대하는 대행사, 협회, 세무·노무 사무소, 장비 공급사 쪽으로. 이들은 보통 온라인 결제에 익숙하다.
- 쿼터 조율: 이 조건 때문에 지루한 산업을 빼지 말 것. 타겟만 옮기고 산업은 남긴다.

### C3. 플랫폼 리스크 — 죽는 스위치가 남의 손에 있는가 (치명 가능)
크롤링, 자동화 매크로, 오픈마켓·메신저 API 우회 등은 상대가 약관 한 줄 바꾸면 하루아침에 끝난다.
회색 전부를 피하자는 게 아니라 **감수 가능한 회색과 죽는 회색을 구분**한다. 판별 질문은 하나다:

> **그쪽이 우리를 막는 것이 그들에게 이득인가, 손해인가?**

- 손해다(우리가 그들 플랫폼의 거래·사용량을 늘려준다) → 감수 가능
- 이득이다(우리가 그들 유료 상품을 대체하거나 트래픽을 뺏는다) → **폐기**
- 모르겠다 → 아이디어에 그대로 "모름"이라 쓰고 순위를 낮춘다

### C4. AI 독립성 — 모델이 좋아지면 사라지는 제품인가
AI 기능 자체가 제품의 전부라면 다음 세대 모델이 기본 탑재하는 순간 없어진다.

> **이 제품에서 AI를 빼면 뭐가 남는가?**

한 줄로 답할 수 있어야 한다. 좋은 답: 남들이 못 가진 데이터 접근권, 업종별 규칙·양식 축적, 기존 시스템 연동, 규제 대응 책임. 답이 "없다"면 순위 최하위로 내린다.

### C5. 확장성 — 매출이 10배면 우리 시간도 10배인가 (치명 가능)
고객 1명이 늘 때 우리가 쓰는 시간을 적는다. 수작업 온보딩, 개별 세팅, 상담이 필요하면 1인 개발자는 매출이 늘수록 목이 졸린다.
- 고객당 내 시간이 **월 30분을 넘으면** 그 부분을 자동화하거나 제품을 바꾼다 (혼자이므로 2인 기준보다 절반으로 본다)
- 고객 50명 시점에 고객 응대에만 주 10시간 넘게 들어가면 그 제품은 혼자 굴릴 수 없다
- 구조적으로 사람 손이 필수인 모델(맞춤 구축, 데이터 수기 입력 대행)은 **폐기**

### C6. 복제 비용과 해자 — 주말에 공짜로 만들어지는가 (치명 가능)

2026년에는 **기능 자체는 거의 다 복제된다.** 실력 있는 개발자가 AI를 붙잡고 주말 이틀이면 웬만한 기능은 따라 만든다. 그러니 "기능이 좋다"는 방어선이 아니다. 두 가지를 따로 묻는다.

**(1) 지금 얼마나 쉽게 복제되는가**
- 주말 이틀이면 복제 가능한가?
- 오픈소스나 무료 템플릿으로 대체될 여지가 있는가?
- **AI에 프롬프트 하나 붙여넣으면 끝나는 일인가?** (이게 걸리면 유료화 근거를 따로 대야 한다)

**(2) 시간이 갈수록 쌓이는 해자가 있는가**
아래 중 **최소 하나**를 구체적으로 지목할 수 있어야 한다. 추상적으로 "노하우가 쌓인다"는 인정하지 않는다.

- **데이터 축적** — 고객이 쓸수록 우리만 갖게 되는 데이터가 생기는가
- **전환 비용** — 고객의 기록·업무가 안에 들어가서 나가기 번거로워지는가
- **연동 자산** — 붙이기 귀찮은 기존 시스템(ERP, 정부 포털, 업종 전용 장비)에 이미 붙어 있는가
- **규제·책임 인수** — 우리가 책임을 지고 신고·인증을 대신하는가
- **유통 장악** — 그 업종 사람들이 모이는 좁은 창구를 우리가 잡았는가
- **업종 규칙 축적** — 양식, 예외 케이스, 지자체별 차이, 판례 같은 것이 계속 모이는가
- 브랜드·신뢰는 단독 해자로 인정하지 않는다 (1인 개발자가 1년 안에 쌓을 수 없다)

**판정**
- 주말 복제 가능 + 해자 경로 없음 → **폐기**
- 주말 복제 가능 + 해자 경로 있음 → 통과. 단 **"해자가 실제로 생기기까지 몇 개월, 고객 몇 명"**을 숫자로 적는다. 그 기간을 못 버티면 의미 없는 해자다
- 복제 자체가 어려움(데이터 접근권, 규제 자격, 오프라인 관계) → 상위로 올린다

**제도 수명 검사** — 해자가 제도에 기대어 있을 때만 추가로 적용한다.
한시 제도(일몰제, 3년 시행, 유예기간부 의무화)를 근거로 삼는 아이디어는 **제도 종료일이 해자 축적 기간보다 먼저 오면 해자가 아니다.**

> 제도 남은 수명 vs 해자가 생기기까지 걸리는 기간 — 어느 쪽이 긴가?

- 제도 수명이 더 길다 → 통과
- 해자 축적 기간이 더 길거나 비슷하다 → 그 아이디어는 **제도가 끝나면 같이 끝난다.** 폐기하거나, 제도가 사라져도 남는 부분(축적된 데이터, 인접 업무로 넓힌 범위)을 아이디어에 포함시켜 다시 쓴다
- 연장 가능성은 근거 없이 낙관하지 않는다. "영구화 논의 중"은 확정이 아니다

**주의**: 해자가 세다고 좋기만 한 게 아니다. 복제가 어려운 이유가 "진입이 어려워서"라면 우리도 못 들어간다. **우리는 들어갈 수 있는데 후발주자는 어려운** 이유여야 한다. 그 비대칭이 어디서 오는지 한 문장으로 답할 것.


### C7. 도메인 접근권 — 그 문제를 계속 깊게 알 수 있는가

해상도 테스트(필터 9)가 "지금 아는가"라면, 이건 **"앞으로 계속 알아낼 수 있는가"**다. 1인 개발의 가장 흔한 실패는 밖에서 상상한 문제를 푸는 것이다.

**(1) 현업 접촉 가능성**
그 일을 실제로 하는 사람 5명에게 **2주 안에 닿을 수 있는가.** 경로를 구체적으로 적는다: 아는 사람, 업종 카페·단톡방, 협회, 전시회, 콜드 DM, 채용공고 낸 회사.
- 닿음 → 통과
- 못 닿음 → 순위 하향. 우회안: **그 업종을 상대하는 중간자부터 만난다** (대행사, 장비 납품사, 세무·노무 사무소, 업종 전문 유튜버). 이들은 만나기 쉽고 여러 현장을 동시에 본다

**(2) 피드백 루프 속도**
만들고 나서 **"이거 틀렸어요"를 며칠 안에 들을 수 있는가.** 6개월 뒤에나 알 수 있는 제품(연 1회 업무, 장기 프로젝트 산출물)은 혼자서는 방향을 고칠 기회가 없다.

**(3) 검증 가능성 — 우리가 결과의 옳고 그름을 판별할 수 있는가**
이게 도메인 지식이 얕을 때 가장 위험한 지점이다. 건설 도면, 법률 문서, 의료 기록처럼 **틀린 결과가 그럴듯해 보이는 분야**에서는, 우리가 맞는지 틀린지 모르면 제품을 만들 수 없다.
- 우리가 직접 판별 가능 → 통과
- 판별 못 함 → 그 분야 현업 1명을 검수자로 붙일 수 있는지 확인. 못 붙이면 **폐기**
- 또는 **판별이 필요 없는 지점으로 제품을 옮긴다** — 정답을 내주는 대신, 현업이 판단하기 쉽게 정리·비교·추적만 해주는 쪽으로

**(4) 공감 거리**
우리가 직접 겪어본 문제인가, 남에게 들은 문제인가. 겪어본 쪽을 상위로 올린다. 단 겪어봤다는 이유만으로 시장이 생기지는 않으므로, 다른 조건을 면제해 주지는 않는다.

## 검증 사다리 — 묻지 않는 방법을 먼저 찾는다

**인터뷰를 기본값으로 두지 않는다.** 1인 개발자에게 "모르는 업체 5곳에 전화해 손해액을 물어라"는 사실상 실행 불가능한 지시이고, 물어도 잘 나오지 않는다. 돈이나 손해를 묻는 질문은 취조처럼 들려서 방어적인 답이 돌아온다.

죽는 조건 실험을 설계할 때는 **아래 0칸부터 차례로 올라가며, 가능한 가장 낮은 칸을 고른다.** 낮은 칸으로 답이 나오면 위로 올라가지 않는다.

**0칸 — 이미 써놓은 글을 읽는다** (사람 접촉 0)
업종 커뮤니티·카페·게시판에서 최근 글을 읽는다. 같은 질문이 반복되는가, 어떤 임시방편을 쓴다고 말하는가. 규제 관련이면 관계 부처가 질의응답·지침을 따로 냈는지 본다. 지침이 나왔다는 것은 질문이 몰렸다는 뜻이다.

**1칸 — 미끼 도구를 던진다** (사람 접촉 0, 가장 권장)
제품의 한 조각을 무료 도구로 떼어내 반나절 만에 만들고, 그 사람들이 모이는 곳에 올린다. 계산기, 양식 생성기, 체크리스트 한 장이면 된다.
그리고 **묻지 않고 본다**: 몇 명이 쓰는가, 어떤 입력을 많이 하는가, 같은 사람이 다시 오는가.
- 어차피 만들 화면 중 하나를 앞당겨 만드는 것이므로 버리는 시간이 없다
- 말보다 행동이 정확하다. 아무도 안 쓰면 그것이 답이고, 반복 사용자가 생기면 그가 첫 고객이다

**2칸 — 방법을 묻는다** (가벼운 접촉)
숫자나 손해를 묻지 않는다. **"이거 보통 어떻게 하세요?"**로 묻는다. 방법은 답하기 쉽고, 답하다 보면 불편한 지점이 알아서 나온다. 금액은 그다음에 따라온다.

**3칸 — 중간자를 만난다**
현업 사장이 아니라 그 업종을 상대하는 쪽부터 간다 — 대행사, 협회, 세무·노무 사무소, 장비 납품사, 업종 전문 유튜버·카페 운영자. 만나기 쉽고 여러 현장을 동시에 본다.

**4칸 — 현업 직접 인터뷰**
여기까지 와야 할 때만 온다. 이 칸을 실험으로 적었다면 **왜 0~3칸으로는 안 되는지 한 줄로 답할 것.**

## 수익성 계산법 (바닥부터 쌓을 것)


**"국내 시장 규모 3조원" 같은 위에서 내려오는 숫자는 단독으로 쓰지 않는다.** 그 3조원 중 우리가 받을 수 있는 돈은 보통 0원이다. 반드시 아래 4단계를 밟아 **셀 수 있는 사업체 수에서 출발**한다. 각 단계에 출처가 없으면 그 숫자는 쓰지 않는다.

### 1단계 — 모집단 세기 (출처 필수)
그 타겟이 국내에 몇 개나 있는가. 찾는 곳:
- 통계청 KOSIS 전국사업체조사 (업종별 사업체 수, 종사자 규모별)
- 국세청 사업자 현황 통계
- 업종 협회 회원사 수, 정부 부처 등록·허가 업체 명부
- 공정위 가맹사업 정보공개서 (프랜차이즈일 때)
- 간접 지표: 그 업종 채용공고 수, 관련 자격증 발급 수, 업종 카페 회원 수

### 2단계 — 도달 가능 모수
1단계에서 아래를 걸러낸 뒤 남는 수를 적는다.
- 규모 조건 (너무 작아 돈 낼 여력이 없는 곳 제외)
- 셀프서브 조건 (C2 — 온라인 결제가 안 되는 층 제외)
- 지역·제도 조건

여기서 보통 10분의 1 이하로 줄어든다. **줄어든 이유를 적는다.**

### 3단계 — 객단가 근거
월 얼마를 받을 것인가. 근거는 하나뿐이다: **지금 이 일에 나가고 있는 돈의 몇 %인가.**
- 대행비로 월 80만원을 쓰던 일이면 월 15~25만원이 자연스럽다
- 알바 시급으로 때우던 일이면 그 시간값 이하
- "경쟁사가 5만원이니 4만원"은 근거가 아니다. 가격 경쟁은 해자가 아니다(C6)

### 4단계 — 필요 고객 수와 침투율
월 1만 달러(약 1,400만원) ÷ 객단가 = 필요 고객 수.
그 수가 **2단계 모수의 몇 %인지** 반드시 계산한다.

- 침투율 **1~3%** → 현실적. 좋음
- **3~10%** → 어렵다. 그 업종에서 사실상 표준이 되어야 가능. 이유를 대야 통과
- **10% 초과** → 사실상 불가능. 객단가를 올리거나 모수를 넓히거나, 아니면 폐기


### 5단계 — 명부를 실제로 받아서 직접 센다

**앞의 1~4단계를 추정으로 채우면 전부 무효다.** "약 2천 곳으로 보인다"는 근거가 아니다. 공개 명부를 내려받아 행을 세고, 그 숫자를 리포트에 적는다.

- 공공데이터포털(data.go.kr), 지자체 표준데이터, 협회 회원사 명부, 인허가 명부를 찾는다
- **접속이 막혀 직접 못 받으면 사용자에게 내려받아 달라고 요청한다.** 파일명과 어디서 받는지를 지목한다. 못 받은 채로 추정치를 쓰지 않는다

#### 깔때기를 표로 보여준다

조건을 한 번에 적용하지 말고 **한 줄에 하나씩** 걸고, 매 줄마다 남은 수를 적는다. 어느 조건에서 시장이 죽는지가 드러난다.

| 조건 | 남은 수 |
|---|---|
| 전체 명부 | 18,105 |
| + 규모 조건 (10~50대) | 2,262 |
| + 지역 조건 (항만 인근) | 574 |
| + 품목 조건 | **확인 불가 — 칼럼 없음** |

#### 데이터 함정을 먼저 본다

세기 전에 이걸 확인하고, 걸린 것은 표 아래에 그대로 적는다.

- **필요한 칼럼이 아예 없을 수 있다.** 그러면 대리 지표(지역·상호·업종)로 좁히고 **"대리 지표다"라고 명시한다.** 대리 지표로 나온 수는 대개 **과대추정**이다
- **빈칸 비율** — 핵심 칼럼이 30% 넘게 비어 있으면 그 수는 하한선이다
- **기준일자가 섞여 있는지** — 지자체별로 제출 시점이 다르면 몇 년치가 섞인다
- **중복** — 본사와 영업소가 따로 잡힌다
- 인코딩은 대개 CP949다. UTF-8로 읽으면 통째로 깨진다

#### 천장 판정

> **천장 = 도달 가능 모수 × 객단가 × 12개월**

이 숫자가 **목표 매출의 3배가 안 되면 경고**다. 100% 침투가 필요한 사업은 없다.

천장이 낮게 나왔을 때 할 일은 셋뿐이고, **"열심히 판다"는 그중에 없다.**

1. **객단가를 올린다** — 그러려면 기능을 더 깊게(청구·정산까지) 가져가야 한다. 지금 기능으로 그 값을 받을 수 있는지 한 문장으로 답한다
2. **모수를 넓힌다** — 어느 조건을 풀면 몇 곳이 늘어나는지 숫자로 적는다
3. **목표를 내린다** — 1인 사업이면 월 500만원도 성공이다. 내렸다고 적고 넘어간다

셋 다 안 되면 폐기한다. 폐기를 미루는 것이 이 스킬의 세 번째로 큰 실패다.
### 천장 테스트 (치명 가능)
**2단계 모수 전부를 고객으로 잡아도 월 1만 달러가 안 되면 폐기한다.** 시작 전부터 천장이 목표보다 낮은 사업이다.
반대로 천장이 목표의 20배를 넘으면 그 시장이 왜 아직 비어 있는지 다시 의심한다. 보통 경쟁자가 이미 있거나, 돈을 안 내는 시장이다.

### 수익 곡선 3단 시나리오
12개월 뒤 월 매출을 세 가지로 적는다. 숫자보다 **각 시나리오를 가르는 조건**이 중요하다.

| 시나리오 | 12개월 후 월 매출 | 이걸 가르는 조건 |
|---|---|---|
| 보수 | | |
| 기본 | | |
| 낙관 | | |

### 마진 확인
- 고객 1명당 월 원가 (API 호출, 스토리지, 외부 서비스 사용료)
- 고객 100명일 때 인프라가 **월 200달러 상한** 안에 들어오는가
- AI를 많이 쓰는 아이디어가 여기서 자주 깨진다. 원가가 객단가의 30%를 넘으면 구조를 바꾼다

### 글로벌 확장 여지
한국에서 만든 것이 그대로 곱해지는가, 처음부터 다시 만들어야 하는가.
- 곱해짐: 제도·양식 의존도가 낮음 → 천장이 크게 올라간다
- 안 곱해짐: 한국 제도에 붙어 있음 → 한국 천장이 곧 전부. 1단계 모수가 그만큼 더 중요해진다
- 한국 특수성 자리(다양성 쿼터)는 보통 안 곱해진다. 결함은 아니지만 **천장을 그만큼 낮게 잡아야 한다**

## 순위 매기는 법

4개를 **좋은 순서대로** 제시한다. 순위는 느낌이 아니라 아래 기준을 위에서부터 적용해 정한다. 앞 기준에서 갈리면 거기서 끝, 동점이면 다음 기준으로 내려간다.

1. **돈의 증거** — 지금 그 일에 실제로 나가는 돈이 확인됐는가 (추정이 아니라 근거 있는 금액)
2. **문제 해상도** — 실패 장면을 구체적으로 쓸 수 있고 실패 유형을 쪼갰는가. 흐릿하면 위로 못 올라간다
3. **문제 적중** — 3층 중 몇 층을 덮는가
4. **경쟁 여백** — 기존 강자가 안 하는 이유가 구조적인가, 단순히 아직 안 한 것인가
5. **시장 천장과 침투율** — 필요 침투율이 낮을수록 위. 천장이 목표에 비해 빠듯하면 아래로
6. **해자(C6)** — 쌓이는 해자를 구체적으로 지목할 수 있는가. 지목 못 하면 아무리 다른 게 좋아도 상위에 올리지 않는다
7. **도메인 접근권(C7)** — 현업 5명에 닿을 수 있고, 결과의 옳고 그름을 판별할 수 있는가
8. **반복성(C1)** — 매일·매주 > 매월 > 분기
9. **셀프서브(C2)** — 온라인 결제 습관이 확인됐는가
10. **AI 독립성(C4)** — AI를 빼도 남는 것이 있는가
11. **플랫폼 리스크(C3)** — 낮을수록 위
12. **확장성(C5)** — 고객당 우리 시간이 적을수록 위
13. **MVP 크기** — 2주에 더 가까울수록 위

각 아이디어 제목 옆에 순위와 **한 줄 근거**를 붙인다. 예: `1위 — 돈의 증거가 유일하게 계약서 단가로 확인됨`

순위가 낮은 것을 "그래도 괜찮다"고 포장하지 말 것. 4위가 약하면 약하다고 쓴다.


---

## 진행 방식: 출발점 선택 + 3단계, 각 단계마다 멈춘다

**중요: 한 번에 끝까지 달리지 말 것.** 각 Phase 끝에서 결과를 보여주고 사용자의 선택을 받은 뒤 다음으로 간다. 사용자가 "그냥 쭉 해줘"라고 명시하면 그때만 연속 진행한다.

---

### Phase 0 — 출발점 고르기

먼저 어느 문으로 들어갈지 묻는다. 대화 맥락에서 이미 답이 나와 있으면 묻지 말고 그대로 간다 (예: 사용자가 특정 산업이나 리포트를 이미 언급했다면 확인만 하고 진행).

- **A. 산업에서 출발** — 최근 구조가 흔들린 업종을 훑어서 고른다 → Phase 1-A
- **B. 리포트에서 출발** — 컨설팅사·리서치 화이트페이퍼를 먼저 읽고, 그들이 "흔들린다"고 지목한 시장에서 역산한다 → Phase 1-B
- **C. 이미 정해진 문제가 있음** — 사용자가 산업이나 문제를 들고 온 경우 → Phase 1을 건너뛰고 Phase 2로

B가 사용자의 기본 전략(라스트 마일 검증법)에 가장 가깝다. 사용자가 망설이면 B를 권한다.

---

### Phase 1-A — 산업 후보 좁히기

목적: 어디를 팔지 정하는 단계. 아직 아이디어를 내지 않는다.

1. 웹 검색으로 **최근 12개월 안에 구조가 흔들린 영역**을 찾는다. 검색 방향 예시:
   - 최근 시행·개정된 국내 법령, 의무화 제도, 신고 의무
   - 플랫폼의 API·수수료·정책 변경 (오픈마켓, 배달, 결제, 메신저)
   - 인력난·고령화로 기존 방식이 무너지는 업종
   - 대형 대행사가 손 떼거나 가격을 올린 영역
2. **주류 서비스가 기피해서 방치된 그레이마켓** 영역을 의도적으로 한 자리 이상 포함한다.
3. 아래 표로 6개 산업 후보를 제시한다.

| # | 산업/영역 | 최근 무엇이 흔들렸나 | 누가 지금 돈을 쓰고 있나 | 2026년성 |
|---|---|---|---|---|

- "2026년성" 칸에는 2023년에는 존재하지 않았던 이유를 한 줄로 쓴다.
- 표 아래에 "관심 가는 번호를 고르시거나, 전혀 다른 산업을 말씀해 주세요"로 끝내고 **멈춘다**.

---

### Phase 1-B — 리포트에서 출발하기

목적: 대기업·컨설팅사가 **이미 돈 들여 검증해 놓은 문제 정의**를 가져와, 그들이 못 가는 마지막 1마일을 찾는다. 아직 아이디어를 내지 않는다.

#### 어디를 읽나
무료로 공개된 것만 본다. 유료 리포트는 대상이 아니다.

- 컨설팅사 화이트페이퍼·연간 전망: PwC, Capgemini, Deloitte, McKinsey, BCG, EY, Accenture
- 리서치·VC 관점: Gartner(공개분), a16z, Bessemer, Battery 등의 산업 에세이
- 스타트업 IR·투자설명 자료, 상장사 사업보고서의 "위험 요소"·"사업의 내용" 항목
- 국내: 삼정KPMG·삼일PwC 산업 인사이트, 업종 협회 실태조사, 정부 부처 백서·용역보고서

검색은 영어와 한국어 양쪽으로 한다. 한국 시장은 국내 협회 자료가 훨씬 구체적일 때가 많다.

#### 무엇을 뽑아내나
트렌드 요약이 아니다. 다음 네 가지만 뽑는다.

1. **그들이 인정한 문제 문장** — 리포트가 "이게 지금 깨지고 있다"고 직접 말한 대목 (출처와 함께)
2. **그들이 제시한 해법** — 보통 대기업용 대규모 전환 프로젝트다
3. **그 해법이 닿지 않는 대상** — 그 처방을 살 수 없는 작은 조직은 누구인가
4. **그래서 그들이 손으로 때우고 있을 일** — 여기가 우리 자리다

이 4단계가 라스트 마일 검증법의 핵심이다. **리포트의 결론을 그대로 따라가면 안 된다.** 리포트는 대기업 예산을 전제로 쓰였으므로, 그 처방을 못 사는 쪽에 남는 잔여 문제를 보는 것이 목적이다.

#### 출력 형식

```
## 흔들리는 시장 (4~6개)

### [시장 이름]
- 출처: (리포트명, 발행사, 연도, 링크)
- 리포트가 인정한 문제:
- 리포트가 내린 처방:
- 그 처방을 못 사는 사람들:
- 그들이 지금 손으로 때우는 일:
- 2026년성: (2023년엔 왜 이 문제가 없었나)
```

마지막에 "이 중 어느 시장을 파볼까요?"로 묻고 **멈춘다**.

#### 제도를 근거로 쓸 때 (가장 자주 틀리는 지점)
법령·고시·의무화를 근거로 삼을 때는 **반드시 시행 상태를 확인하고 명시한다.** 개정안 발표 기사와 실제 시행은 1~2년 차이가 나는 일이 흔하고, 발표 시점 기사만 읽으면 이미 시행된 것처럼 읽힌다.

각 제도에 다음을 붙인다.
- **시행 완료** (시행일 명시) → 돈이 이미 나가고 있을 수 있다. 가장 좋은 근거
- **공포·확정, 시행일 미도래** (시행일 명시) → 준비 수요는 있으나 아직 아무도 돈을 안 쓴다
- **입법예고·의견수렴 단계** → 내용이 바뀔 수 있다. **돈 필터에 걸리므로 이 단계 제도만으로는 아이디어를 만들지 않는다**

"내년부터", "추진 중"이라는 표현이 보이면 시행 전이다. 기준일은 오늘 날짜이지 기사 작성일이 아니다.

#### 지켜야 할 것
- **리포트 내용을 지어내지 말 것.** 검색으로 실제 문서를 확인하지 못했으면 그 항목은 쓰지 않는다. 못 찾았으면 "이 분야는 공개 자료를 못 찾았다"고 그대로 말한다.
- 리포트 원문을 길게 옮기지 말고 요점을 자기 말로 정리한다.
- 리포트가 다 같은 소리를 하는 영역(모두가 "AI 도입이 시급하다"고 쓰는 곳)은 기회가 아니다. **여러 리포트가 서로 다른 진단을 내놓거나, 한 리포트만 구체적 수치를 대는 지점**이 더 쓸모 있다.

---

### Phase 2 — 근거 조사 (라스트 마일 검증법)

목적: 고른 산업 안에서 "진짜 아픈 지점"을 특정한다. 아직 아이디어를 내지 않는다.

두 층을 모두 조사한다. 한쪽만 하면 이 Phase는 실패한 것이다.

**Phase 1-B로 들어온 경우**: 위층은 이미 한 번 훑었으므로 반복하지 말고, 고른 시장 하나에 대해서만 더 깊이 판다(그 시장을 다룬 다른 리포트, 관련 상장사 사업보고서). 대신 **아래층 현장 확인에 무게를 싣는다.** 리포트만 보고 아이디어로 직행하는 것이 이 경로의 가장 큰 함정이다 — 리포트는 팔기 위해 쓰인 문서라서 문제를 실제보다 크고 급하게 그린다.

**위층 — 검증된 문제 정의 찾기**
대형 컨설팅사 무료 화이트페이퍼(PwC, Capgemini, Deloitte, McKinsey), Gartner·a16z 등 리서치, 그리고 관련 스타트업의 IR·투자 자료를 검색한다.
여기서 얻을 것은 트렌드가 아니라 **"업계가 이미 인정한 문제 문장"**이다. 그 문장을 그대로 가져오되, 남들이 읽는 방향이 아니라 "그 큰 문제의 마지막 1마일에서 누가 손으로 때우고 있나"로 재해석한다.

**아래층 — 현장 확인**
Reddit, Hacker News, Indie Hackers, X, GitHub issues, Discord, 앱스토어·네이버 리뷰, 국내 업종 커뮤니티·카페를 검색한다.
찾는 것은 의견이 아니라 **불만의 물증**이다: 같은 하소연이 반복되는가, 사람들이 어떤 임시방편(엑셀, 카톡, 알바, 대행사)을 쓰고 있다고 말하는가.

출력:

```
## 흔들리는 지점 (3~5개)

### [지점 이름]
- 위층 근거: (리포트가 뭐라고 했는지 + 출처)
- 아래층 물증: (누가 어디서 뭐라고 불평하는지, 반복되는가)
- 지금 이 일을 누가 어떻게 때우고 있나:
- 여기에 나가는 돈의 흔적:
- 대기업이 안 들어오는 이유:
```

마지막에 "이 중 어디를 파볼까요?"로 묻고 **멈춘다**.

근거가 약하면 약하다고 말한다. 리포트 내용을 지어내지 말 것 — 못 찾았으면 "못 찾았다"가 정답이다.

---

### Phase 3 — 아이디어 생성과 자기 반박

목적: 후보를 만들고, 대부분을 스스로 죽인다.

0. **먼저 문제를 3층으로 쪼갠다** (필터 7). 아이디어를 쓰기 전에 인지층·진단층·해결층에 각각 무엇이 들어가는지 적는다. 이 단계를 건너뛰면 거의 반드시 증상 하나짜리 아이디어가 나온다.
1. **내부적으로 12개**를 만든다. (전부 보여주지 않는다)
2. 위의 절대 필터로 대부분을 폐기한다(보통 8개 안팎). 폐기 전에 경쟁 현실성(필터 6)을 **웹 검색으로** 확인한다.
3. 살아남은 것에 **지속 조건 7종(C1~C7)과 수익성 계산법을 적용**한다. C3·C5·C6·C7의 치명 조건, 그리고 천장 테스트에 걸린 것만 추가 폐기하고, 나머지는 걸린 지점과 우회안을 기록해 둔다.
4. **4개**를 아래 15항목 카드로, **순위 매기는 법에 따라 좋은 순서대로** 제시한다. 다양성 쿼터를 만족시킨다.
5. 폐기한 것들은 사유 표로 요약해 보여준다.
6. 마지막에 **최종 추천 1개**와 그 이유를 쓴다. 보통 1위가 되지만, 1위와 다르다면 왜 다른지 반드시 설명한다.

폐기 표 형식:

| 폐기 아이디어 | 폐기 사유 |
|---|---|

사유는 "별로여서"가 아니라 **어떤 필터에 걸렸는지**로 쓴다. (예: "돈 필터 — 지금 아무도 이걸 위해 돈을 안 쓰고 있음", "2023년 테스트 탈락")

---

## 아이디어 카드: 15항목 (형식 고정)

```
## [아이디어 이름]

1. 실패 장면 — 누가, 어떤 도구로, 무엇을 하려다, 어느 순간 막히는지 30초 장면으로
2. 고른 실패 유형 — 이 주제 안의 실패 유형을 3개 이상 나열하고, 그중 무엇을 고르는지와 나머지를 버리는 이유
3. 왜 지금 — 2026년에만 이 문제가 존재하는 이유 (2023년엔 왜 없었나)
4. 타겟 — 업종·규모·직책까지 구체적으로 (예: 직원 5~20명 폐기물 수집업체의 사무직 1인)
5. 정량 고통 — 월 몇 시간 / 월 얼마 / 실수 시 손실 얼마
6. 현재 땜질 방식 — 지금 엑셀·카톡·알바·대행사 중 무엇으로 때우는가
7. 문제 적중도 — 인지 / 진단 / 해결 3층 중 무엇을 덮고 무엇을 안 덮는지 명시.
   안 덮는 층이 있으면 "그래도 돈을 내는 이유"를 답할 것
8. 화면 3개 MVP — 딱 세 화면으로 무엇을 만들지 (2주 안에 가능한 크기)
9. 첫 고객 10명 채널 — 어디에 가면 이 사람들이 모여 있나 (구체적 카페·협회·전시회·검색어)
10. 시장 크기와 수익 — '수익성 계산법'에 따라 표로

    | 항목 | 값 | 출처 / 근거 |
    |---|---|---|
    | 모집단 | 개 | |
    | 도달 가능 모수 | 개 | (무엇을 걸러냈는지) |
    | 객단가 | 월 원 | (현재 나가는 돈의 몇 %) |
    | 필요 고객 수 | 명 | |
    | 필요 침투율 | % | |
    | 천장 (모수 전부) | 월 원 | |
    | 고객당 원가 | 월 원 | |

    - 12개월 후 월 매출: 보수 / 기본 / 낙관 + 각각을 가르는 조건
    - 글로벌로 곱해지는가: 예 / 아니오 + 이유
    - 출처 없는 숫자는 "추정"이라고 표시한다. 추정만으로 채워진 표는 근거가 없는 것
11. 경쟁 지형 — 표로. 국내·해외·오픈소스·엑셀 땜빵·**앱스토어 앱**까지 실제 이름을 적는다

    | 기존 플레이어 | 어디에 있나 (웹/Play/App Store) | 무엇을 하나 | 왜 이 고객을 못 챙기나 |

    - **앱스토어 칸이 비어 있으면 이 표는 미완성이다.** 필터 6의 앱스토어 절차를 돌리고 다시 쓴다. 앱을 못 찾았으면 넣은 검색어를 적는다
    - 경쟁자를 **층으로 나눈다.** 같은 업종이라고 같은 경쟁자가 아니다. 보통 (a) 일감 찾는 앱 (b) 업무 관리 SaaS (c) 개인 장부 앱으로 갈리고, 우리와 진짜 부딪히는 건 대개 (b)다. 제일 눈에 띄는 (a)를 경쟁자로 착각하지 말 것
    - 아래에 **"왜 기존 강자가 이걸 안 하는가"** 한 문장 필수
    - 기존 앱이 우리 기능을 **몇 주면 붙일 수 있는지** 한 문장으로 답한다. "몇 주"면 그건 해자가 아니다 (12번으로 넘긴다)
    - 경쟁자가 하나도 없으면 "아무도 안 한다"가 아니라 "왜 아무도 안 하는가"를 의심하고 답을 쓴다
12. 방어선 — 다음 셋을 각각 답한다
    - 주말 이틀이면 복제되는가 / 무료·오픈소스로 대체 가능한가
    - 쌓이는 해자는 무엇인가 (C6 목록 중 하나를 지목, "노하우"는 불가)
    - 그 해자가 생기기까지 몇 개월, 고객 몇 명인가
13. 죽는 조건 실험 — 이 아이디어가 틀렸음을 가장 빨리 증명할 단 하나의 실험.
    **'검증 사다리'의 가장 낮은 칸부터 고를 것.** 인터뷰를 1순위로 쓰지 않는다
14. 지속 조건 점검 — 표로. 걸린 것은 숨기지 말고 우회안을 적는다

    | 조건 | 판정 | 근거 / 우회안 |
    |---|---|---|
    | C1 반복성 | 매일·매주·매월·분기·연1회 | |
    | C2 셀프서브 | 확인됨 / 불확실 / 타겟 이동 필요 | |
    | C3 플랫폼 리스크 | 없음 / 감수 가능 / 모름 | |
    | C4 AI 독립성 | AI를 빼면 남는 것 | |
    | C5 확장성 | 고객 1명당 우리 시간 월 O분 | |
    | C6 해자 | 복제 난이도 + 지목한 해자 종류 | |
    | C7 도메인 접근권 | 현업 접촉 경로 / 결과 판별 가능 여부 | |

15. PMF 판정 — 한국 / 글로벌 각각에 대해 있다·없다·모르겠다 + 이유
```

각 항목은 짧게. 15항목을 채우려고 말을 지어내지 말고, 모르면 "확인 필요"라고 쓴다.

## 어조

직설적이고 실용 우선. 격려나 포장은 넣지 않는다.
아이디어가 약하면 약하다고 먼저 말한다. 4개를 억지로 채우느라 필터를 통과 못 한 것을 끼워 넣는 것이 이 스킬의 가장 큰 실패다 — 2개만 살아남았으면 2개만 내고 "나머지는 필터를 못 넘었다"고 말한다.

## 흔한 실패 모드

- 웹 검색 없이 기억으로 아이디어를 냄 → 2023년 테스트를 자동 탈락
- 리포트 인용을 지어냄 → 근거 전체가 무효
- 산업은 다른데 실제로는 전부 "AI로 자동화해주는 도구" → 다양성 쿼터 위반
- 타겟이 "중소기업" 수준으로 뭉뚱그려짐 → 4번·7번을 쓸 수 없으면 아이디어가 아님
- 단계를 건너뛰고 Phase 3으로 직행 → 근거 없는 아이디어만 나옴
- **증상 하나를 문제 전체로 착각** → 큰 문제 이름을 붙여놓고 그 안의 작은 조각만 푸는 도구를 제시. 문제를 3층으로 안 쪼갰을 때 반드시 발생한다
- **시행 전 제도를 시행된 것으로 착각** → 개정안 기사와 시행일은 다르다. 시행 상태를 안 적으면 없는 고통을 근거로 삼게 된다
- **주제를 문제로 착각** → "건설업 AI가 어렵다"는 주제다. 실패 유형을 3개로 못 쪼개면 아직 아이디어를 쓸 단계가 아니다
- **검증 방법을 인터뷰로만 적음** → 혼자서 실행 못 할 계획은 계획이 아니다. 0~1칸으로 답이 나오는지 먼저 볼 것
- **밖에서 상상한 문제를 품** → 현업 5명에 닿을 경로가 없으면, 만든 뒤 6개월 동안 틀린 줄도 모른다
- **시장 규모를 위에서 내려받음** → "국내 OO시장 3조원"은 우리 매출과 무관하다. 셀 수 있는 사업체 수에서 시작하지 않으면 숫자 전체가 무효
- **"기능이 좋다"를 방어선으로 착각** → 2026년엔 기능은 주말이면 복제된다. 쌓이는 해자를 지목 못 하면 방어선이 없는 것
- **자료는 읽었는데 구조를 안 그림** → 사실을 읽는 것과 그 사실이 무엇을 뜻하는지 아는 것은 다르다. "현실을 보는 법" 여섯 개를 실제로 써서 만들지 않았으면, 그 아이디어는 읽기만 하고 본 적은 없는 것이다
- **2차 효과를 안 봄** → "그래서 어떻게 되나"를 한 번만 묻고 멈추면 가장 큰 자산과 가장 큰 위협을 뒤바꾼다
- **지지 증거만 모음** → 가설을 적은 자리에서 "이게 틀렸다면 무엇이 보일까"를 같이 적지 않았으면 조사가 아니라 변론이다
- **내가 가정한 숫자가 전제로 굳음** → 몇 번 굴린 숫자는 출처를 잃는다. 등급을 안 적었으면 그 계산은 근거가 없다
- **경쟁을 기억으로 판단** → "비슷한 게 없는 것 같다"는 확인이 아니다. 검색해서 이름을 적지 못하면 그 아이디어는 검증되지 않은 것
- **웹 검색만 하고 앱스토어를 안 봄** → 현장 직군 제품은 웹에 안 보이고 앱스토어에만 있다. 설치 수 수만 건짜리 경쟁자를 통째로 놓친다. 필터 6의 앱스토어 절차는 선택이 아니다

## 이 스킬이 하지 않는 것

아이디어 발굴까지가 범위다. 선택된 아이템의 검증 실행 계획, MVP 구현, 기술 스택 결정, 마케팅은 이 스킬 밖이다. 사용자가 그쪽으로 넘어가면 스킬을 닫고 일반 대화로 진행한다.
