# 중단 기록 — 운임근거함

**중단일: 2026-09-20**
**단계: Day 0 (미끼 도구 배포 직전). 본체는 A4까지 만들어진 상태.**

`docs/00-PLAN.md`에 적어 둔 대로다. **중단은 실패가 아니다. 이 단계의 목적이 그거다.**

---

## 왜 중단하나

커뮤니티에서 직접 확인한 것 넷. 이 중 1번이 결정적이다.

1. **대기료 마찰은 있지만, 대부분 어찌저찌 잘 해결하고 있다**
2. 2026년 고시로 법적 제지가 생겨 **앞으로 더 잘 해결될 것으로 보인다**
3. 설령 문제라 해도 **이걸 위해 월 20만원을 낼 사람이 없다**
4. 따라서 이 아이디어는 좋지 않다

이 관찰은 우리가 그때까지 모은 어떤 간접 증거보다 세다. 제도 문서·언론 기사·
공공데이터는 전부 **문제가 존재할 수 있다**까지만 말했고, **사람들이 괴로워하는지**는
말하지 못했다.

---

## 무엇을 잘못 알았나

### 1. 제도 변화를 수요로 착각했다

이 아이디어의 근거는 전부 제도 쪽이었다 — 안전운임제 재도입, 연중 요율 개정,
새 서식 도입, 신고센터 운영. `00-PLAN.md`의 "아직 모르는 것 2번"에 **정량 고통이
미확인**이라고 스스로 적어 놓고도, 그 뒤로는 그것을 확인된 사실처럼 다뤘다.

**새 법이 생겼다 ≠ 사람들이 괴롭다.**

### 2. 법이 문제를 풀면 제품이 필요 없어진다 — 이걸 거꾸로 봤다

세션 내내 "화주에게 서명 의무를 지운 조항(별표1 24.다)"을 **우리 제품의 법적 무기**로
취급했다. 실제로는 반대다. **법이 서명을 강제하면 서명을 받아내는 도구가 필요 없어진다.**

규제를 계기로 삼는 아이디어의 고유한 함정이다. 규제는 시장을 열기도 하지만,
그 규제가 문제를 직접 해결해 버리면 시장을 열기 전에 닫는다.

### 3. 고통을 느끼는 사람 · 돈을 내는 사람 · 관찰한 채널이 전부 달랐다

고시 별표1 24조 본문은 **대기료를 운수사업자가 차주에게 우선 지급한 뒤 화주에게
청구**하도록 한다. 즉 손실을 떠안는 쪽은 차주가 아니라 운송사다. 그런데 우리가
보려던 채널(차주 카페)에는 운송사 대표가 없다.

**이 구멍은 끝까지 메우지 못했다.** 운송사 대표에게 직접 물었으면 다른 답이
나왔을 가능성이 남아 있다. 다만 1번 관찰("마찰이 잘 해결된다")이 사실이라면
결론은 바뀌지 않는다.

### 4. 만들기 전에 그들의 말을 읽지 않았다

이게 과정의 핵심 실패다. 순서가 이랬다.

```
기획 문서 → 본체 A1~A4 구현 → 미끼 도구 구현 → 고시 원문 대조
  → 경쟁 조사 → 모집단 카운트 → **그제서야 커뮤니티를 읽음** → 중단
```

**커뮤니티를 한 번 읽는 데 든 시간은 몇십 분이었고, 그게 앞의 전부를 무효로 만들었다.**
순서가 뒤집혀 있었다.

## 다음에 다르게 할 것

1. **아이디어의 근거가 제도 변화 하나뿐이면, 그건 근거가 아니라 계기다.** 계기 말고
   사람을 찾는다
2. **규제 기반 아이디어는 "그 규제가 문제를 직접 해결해 버리는가"를 먼저 묻는다.**
   해결해 버리면 시장은 열리지 않는다
3. **고통을 느끼는 사람과 돈을 내는 사람이 다를 수 있다.** 관찰할 채널을 고를 때
   **돈을 내는 쪽**이 있는 곳을 고른다
4. **"어찌저찌 해결하고 있다"는 답이 나오면 그 아이디어는 끝이다.** 비타민이고,
   비타민은 팔리지 않는다
5. **코드를 한 줄 쓰기 전에 그들이 쓴 글을 먼저 읽는다.** 못 찾으면 만들지 않는다
