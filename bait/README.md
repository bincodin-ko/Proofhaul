# 안전운임 확인서 생성기 (미끼 도구)

`docs/03-BUILD-PROMPT.md`의 **명령 0**, `docs/06-FAST-TRACK.md`의 **A8**.

**제품이 아니라 실험이다.** 이 도구가 실제로 쓰이는지 관찰하는 것이 목적이고,
판정 기준은 `docs/00-PLAN.md`의 "Day 0+14 — 판정"에 있다. 2주간 10건 미만이면 중단한다.

본체(운임근거함)와 코드를 공유하지 않는다. 독립된 Next.js 앱이고, 곧 버릴 수 있다.

## 하는 일

국토교통부고시 제2026-55호의 **별지 제1~6호서식 그대로** 폰에서 적고, 서명받고,
한글이 박힌 PDF로 내려받는다.

- 대기시간 확인서 (컨테이너 제4호 / 시멘트 제6호)
- 험로 · 오지 확인서 (컨테이너 제3호 / 시멘트 제5호)
- 컨테이너 세척 · 손상 교체 확인서 (제1호 / 제2호)

서명을 받는 길은 두 가지다.

1. **현장에서 바로** — 기사가 폰을 내밀고 화주 담당자가 그 자리에서 서명한다
2. **링크로** — 카톡으로 링크를 보내면 화주가 자기 폰에서 열어 서명한다.
   서명된 PDF는 화주가 기사에게 다시 보내준다

그리고 **이 폰 안에** 두 가지가 남는다.

- **내 정보** — 차량번호·차주 성명·운수사 명. 다음 확인서에서 자동으로 채워진다
- **내가 만든 확인서 목록** — `서명 완료` / `서명 기다리는 중` / `받음`.
  PDF를 다시 만들거나 링크를 다시 보낼 수 있다

로그인 없음. DB 없음. 설치 없음.

## 하지 않는 일

- **요율·할증률·기준시간 숫자를 하나도 넣지 않는다.** 국토교통부 고시 원문 대조가
  끝나지 않았다(`docs/02-RULES-v2026.md` B절). 추정값을 넣는 순간 이 도구는 틀린 값을
  퍼뜨리는 도구가 된다
- **대기시간은 시각만 기록한다.** 몇 시간 초과인지 계산하지 않는다. 기산 기준이
  도착 시각인지 접수 시각인지조차 확정되지 않았다
- 계정, DB, 결제, 운임 금액 계산 없음
- 개인정보를 서버로 보내지 않는다

계산이 필요한 자리는 화면과 PDF 양쪽에 **"미지원"**과 그 이유를 인쇄한다.
빈칸이나 0으로 두지 않는다.

## 개인정보

입력값·서명 이미지·PDF는 전부 브라우저 안에서만 처리된다. 서버로 가지 않는다.

**저장은 이 폰 안에서만 한다.** 내 정보와 확인서 목록은 `localStorage`에 있고,
첫 화면에 그 사실과 "전부 지우기" 버튼이 같이 있다. 저장이 막혀 있어도
(시크릿 모드, 저장소 차단) 도구는 그대로 돌아간다 — 읽기·쓰기 실패는 전부 무시한다.

**링크 서명도 서버를 쓰지 않는다.** 확인서 내용을 주소의 `#` 뒤(프래그먼트)에 싣는다.
프래그먼트는 브라우저가 서버로 보내지 않으므로, 우리 접속 기록에도 남지 않는다.
대신 링크를 받은 사람은 내용을 볼 수 있다 — 종이 확인서를 건네는 것과 같은 수준이고,
링크를 만드는 화면에서 그 사실을 그대로 적어 둔다. 읽는 쪽은 아무것도 믿지 않는다:
서식에 있는 항목 이름만 받고, 길이를 자르고, 제어문자를 버린다 (`lib/link.ts`).

- PDF는 `pdf-lib`로 클라이언트에서 만든다. 서버 렌더를 쓰면 입력값이 서버를 지나가므로 안 쓴다
- `next.config.ts`의 CSP `connect-src 'self'`가 이 약속을 브라우저가 강제하게 만든다
- 서버에 남는 것은 아래 카운터 한 줄뿐이다

## 측정

`POST /api/count`가 받는 값은 두 개다.

```json
{"evt":"cert_generated","kind":"WAIT","repeat":"first","via":"here"}
```

- `kind` — 확인서 종류 (종류별 분포)
- `repeat` — `first` / `2-3` / `4+` (재방문 여부. localStorage 기준, 구간만 보낸다)
- `via` — `here`(현장에서 바로) / `request`(링크로 요청함) / `link`(링크 받은 쪽이 서명함)

## 설문 — 도구가 답할 수 없는 것을 묻는다

몇 번 쓰였는지는 카운터가 센다. **살 만한 물건인지는 그걸로 알 수 없다.**
그래서 확인서를 다 만든 직후, 이 도구가 쓸모 있다는 걸 방금 확인한 그 순간에
객관식 세 개를 묻는다 (`lib/survey.ts`).

지키는 규칙 셋.

1. **PDF를 먼저 준다.** 답을 안 해도 이미 받은 뒤다. 설문이 도구를 인질로 잡지 않는다
2. **주관식도 연락처도 없다.** 고른 보기 값 하나만 서버로 간다. "개인정보를 서버로
   보내지 않는다"는 약속을 설문 때문에 깨지 않는다
3. **가격을 직접 묻지 않는다.** "얼마면 쓰시겠어요"는 쓸모없는 답을 준다.
   대신 **지금 얼마를 잃고 있는지**를 묻는다. 가격은 그 숫자에서 나온다

묻는 사람에 따라 문항이 다르다.

| 누구 | 묻는 것 |
|---|---|
| 확인서를 만든 쪽 (`maker`) | 역할 · **작년에 못 받은 대기료** · 지금은 어떻게 받는지 |
| 링크를 받아 서명한 쪽 (`signer`) | 역할 · **서명 요청을 받으면 어떻게 하는지** · 평소 요청 방식 |

두 번째 줄이 이 실험에서 제일 귀한 답이다. 화주 담당자에게 직접 물을 방법이
달리 없다. 한 번 답한 사람에게는 다시 묻지 않는다.

**`via`가 이번 실험의 핵심 질문이다.** `request`는 쌓이는데 `link`가 0이면,
링크를 보내도 화주가 서명하지 않는다는 뜻이다. 그건 제품의 핵심 가정이 틀렸다는
신호이고, 화면 3(미확보 목록)을 만들 이유가 오히려 더 커진다는 뜻이기도 하다.

IP도 UA도 입력값도 기록하지 않는다.

### 로그만 보고 세면 안 된다

**Vercel Hobby 요금제의 런타임 로그 보관 기간은 1시간이다.** 2주를 관찰해야 하는데
1시간 뒤에 사라지므로, 대시보드 로그만 믿으면 관찰 자체가 성립하지 않는다.
(30일 보관은 Observability Plus이고 Hobby에서는 살 수 없다.)

그래서 `COUNTER_WEBHOOK_URL`로 한 줄씩 밖으로 내보내고, 받는 쪽을 구글 시트로 둔다.
스크립트와 붙이는 순서는 `tools/counter-sheet.gs` 주석에 있다. 공짜이고, 데이터는
본인 계정에 남고, 세는 건 시트 함수로 끝난다.

생성 횟수는 행 수, 종류별 분포는 `kind`, 재방문은 `repeat`로 센다.

## 한글 PDF

PDF에 한글 폰트를 임베드하지 않으면 글자가 전부 깨진다. 그래서 나눔고딕을 싣는다.

두 가지가 걸려 있고 둘 다 처리해 두었다. `public/fonts/README.md`와
`lib/pdf.ts`의 주석에 이유가 적혀 있다.

1. **`subset: false`로 임베드한다.** pdf-lib(fontkit)의 TrueType 서브셋터가 합성
   글리프를 제대로 옮기지 못한다. 나눔고딕의 한글 음절은 대부분 합성 글리프라
   `subset: true`로 만들면 PDF 안의 글자가 통째로 빈칸이 된다. 텍스트 추출은 멀쩡해서
   눈으로 열어보기 전까지 알아채기 어렵다. 값: PDF 한 장이 약 750KB
2. **폰트에 없는 글자는 만들기 전에 막는다.** 나눔고딕에는 한자가 없다.
   `lib/font-coverage.ts`가 폰트의 cmap을 그대로 담고 있어서, 서명 단계로 넘어가기 전에
   어떤 글자가 문제인지 알려준다. 서명까지 받은 문서에서 글자가 사라지는 것이 가장 나쁘다

폰트를 바꾸면 커버리지 표를 다시 만든다.

```
pip install fonttools
python3 tools/gen-font-coverage.py public/fonts/NanumGothic-Regular.ttf
```

## 검증

```
npm run build && npm start &   # http://localhost:3311 로 띄운 뒤
npm run e2e
```

`tests/e2e/run.mjs`가 명령 0의 요구사항을 실제로 돌려서 확인한다. 만든 PDF는
`.e2e-out/`에 남으므로 열어서 한글을 눈으로 볼 수 있다.

**"개인정보를 서버로 보내지 않는다"는 화면만 봐서는 확인할 수 없다.** 그래서
흐름 내내 나가는 요청을 전부 붙잡아 입력값이 섞여 나가는지 본다. 카운터는
`navigator.sendBeacon(Blob)`으로 나가는데 Playwright의 `request.postData()`는
Blob 본문에 `null`을 주기 때문에, 그것만 믿으면 **본문을 읽지도 않고** 통과시키게
된다. CDP의 `Network.getRequestPostData`로 본문을 실제로 받아와서 검사한다.

## 배포 (Vercel 무료 티어)

이 폴더가 프로젝트 루트다. 저장소 루트가 아니다.

1. Vercel에서 저장소를 연결하고 **Root Directory를 `bait`로** 지정한다
2. 프레임워크는 Next.js로 자동 인식된다. 빌드 설정은 건드릴 것이 없다
3. 환경변수 `COUNTER_WEBHOOK_URL`을 넣는다. **선택이 아니다** — 위 "측정" 절 참조.
   없으면 카운터가 1시간 뒤 사라져서 2주 관찰을 할 수 없다

무료 티어 안에서 돈이 나갈 구석이 없다. DB도 스토리지도 외부 API도 쓰지 않고,
2MB 폰트는 정적 자산이라 CDN에서 나간다(brotli 약 430KB, PDF를 만들 때만 받는다).

## 확인한 것

`npm run build` 후 실제 브라우저(iPhone 13 규격)로 돌려서 확인했다.

- 세 종류 모두 입력 → 서명 → PDF 내려받기까지 동작
- PDF를 실제로 열어 **한글이 깨지지 않는 것을 눈으로 확인** (드문 음절 뷁 쀍 똠 짊 옰 휭 포함)
- 파일명도 한글로 나온다 (`대기시간확인서_2026-09-14_12가3456.pdf`)
- 가로 스크롤 없음, 첫 화면에서 2MB 폰트를 받지 않음 (첫 로드 107KB)
- 한자를 넣으면 서명 전에 막힌다
- 서버 로그에 입력값·이름·차량번호가 남지 않는다
