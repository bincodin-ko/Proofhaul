# 압축 계획 — 숫자 없이 먼저 다 만든다

`00-PLAN.md`의 Day 1~14 일정을 이 문서로 대체한다. 순서만 바뀌고 내용은 같다.

## 핵심 아이디어

막히는 건 **계산 규칙의 숫자**뿐이다. 그 외 전부 — 스키마, 인증, 세 화면, 서명 흐름, PDF, 보안, 개인정보 — 는 숫자 하나 없이 지금 만들 수 있다.

그래서 **규칙을 인터페이스로 먼저 만들고 구현은 비워둔다.** 계산이 필요한 자리는 "미지원"으로 표시하고, 나중에 고시 원문을 확보하면 **숫자만 채운다.** 앱을 다시 건드릴 필요가 없다.

```ts
// rules/types.ts  ← 지금 만든다
export interface RuleSet {
  version: string;                 // "2026.02", "2026.08"
  waitThreshold(cargo: CargoType): Minutes | null;   // null = 미확정
  surcharge(input: SurchargeInput): Amount | null;
  fuelAdjustment(date: Date): Ratio | null;
}

// rules/v2026-02.ts  ← 지금은 전부 null을 반환
// 원문 대조 후 숫자만 채워 넣는다
```

`null`이 오면 화면은 "미지원"을 띄우고 값을 지어내지 않는다. **이게 이 계획의 안전장치다.**

## 차단 목록 — 실제 숫자·데이터가 필요한 것

이것들만 나중이다. 나머지는 전부 지금.

| 항목 | 무엇이 필요한가 | 어디서 | 언제 |
|---|---|---|---|
| 대기료 기산 기준 | 규격별 초과 기준 시간 | 국토부 고시 원문 | Phase B |
| 할증 계산 | 가산 방식, 시간 비례 규칙, 상한 | 고시 + 운영지침 | Phase B |
| 개별 부대비용 금액 | 검색대 통과 등 | 고시 원문 | Phase B |
| 유가 연동 | 적용 시점과 폭 | 고시 + 8월 개정분 | Phase B |
| 확인서 필수 기재 항목 | 표준 서식 원문 | 고시 별지 | Phase B |
| 고객당 원가 | SMS 단가, 스토리지 단가 | 벤더 가격표 | Phase C |
| 모집단 | 업종별 사업체 수 | 공공데이터포털 | Phase C |

**Phase A는 이 표를 전혀 건드리지 않는다.**

# Phase A — 숫자 없이 전부 만든다

예상 1.5~2일. 명령은 하나씩 준다.

## A1. 프로젝트 골격과 규칙 인터페이스 (2시간)

```
docs/01-SPEC.md와 docs/05-SECURITY.md를 읽어줘.

Next.js(App Router) + Postgres 프로젝트를 초기화하고, 01-SPEC의
데이터 모델대로 스키마와 마이그레이션을 만들어줘.

반드시 지킬 것
- 모든 id는 UUID. 자동증가 정수 금지
- evidence는 token이 아니라 token_hash를 저장
- 모든 쿼리에 company_id 조건을 강제하는 지점을 한 곳으로 모아줘
- Supabase면 RLS를 켜줘

그리고 rules/ 모듈을 인터페이스로 먼저 만들어줘.
- rules/types.ts: RuleSet 인터페이스
  (waitThreshold, surcharge, fuelAdjustment — 전부 null 반환 가능)
- rules/v2026-02.ts, rules/v2026-08.ts: 지금은 모든 함수가 null을 반환
- rules/index.ts: 날짜를 주면 해당 시점 버전을 돌려주는 선택기
- 각 파일 상단에 "원문 미대조 — docs/02-RULES-v2026.md B절 참조" 주석

절대 하지 말 것
- 어떤 숫자도 넣지 마라. 추정값, 예시값, 임시값 전부 금지
- null을 0으로 대체하지 마라
```

## A2. 인증과 테넌트 분리 (2시간)

```
운송사 로그인을 만들어줘. 이메일 + 비밀번호만. 소셜 로그인 없음.

- 비밀번호는 bcrypt 또는 argon2
- 세션 쿠키 httpOnly, secure, sameSite=lax
- 로그인 시도 속도 제한
- 로그인·비밀번호 재설정에서 계정 존재 여부가 드러나지 않게 응답 통일

끝나면 계정 2개를 만들어서, 한쪽 계정으로 다른 쪽 company_id의
데이터에 접근을 실제로 시도하고 결과를 보고해줘.
```

## A4. 토큰과 서명 페이지 (4시간) — 가장 중요

```
docs/05-SECURITY.md의 "위협 1 — 토큰" 절을 먼저 읽어줘.

화면 2를 만들어줘.

요청 쪽 (로그인 상태)
- 증빙 종류 선택 → 토큰 링크 생성
- CSPRNG 32바이트, DB에는 해시만, 상수 시간 비교, 만료 7일
- 토큰 1개 = 증빙 1건
- 링크 복사 / 발송, 상태 표시(요청됨·서명됨·만료)

서명 쪽 (로그인 없음)
- 모바일 한 화면
- 서명 전 노출 정보는 최소한으로: 운송 건 번호, 날짜, 품목, 요청 회사명
- WAIT: 도착·상차·하차 시각을 기록만 한다.
  rules의 waitThreshold가 null이면 초과 시간 자리에 "미지원"을 띄운다
- ROUGH_ROAD / WASH_SWAP: 체크 + 사진 첨부
- 손가락 서명 캡처
- 저장 시 signer_ip, signer_user_agent 기록
- 없는 토큰과 만료된 토큰의 응답을 구분할 수 없게
- 토큰 조회에 IP 속도 제한

끝나면 토큰 문자열을 임의로 바꿔 다른 증빙에 접근을 시도하고
결과를 보고해줘.
```

## A5. 파일 처리와 PDF (3시간)

```
- 업로드: 확장자가 아니라 실제 내용으로 타입 검사. SVG 금지.
  서버에서 재인코딩하면서 EXIF 제거. 크기·개수 상한
- 저장: 버킷 비공개. 서명된 URL 또는 권한 검사 프록시
- PDF: 서버에서 HTML → PDF. 한글 폰트 임베드 필수.
  렌더러의 원격 리소스 로딩을 끌 것 (SSRF 차단)
- PDF 내용: 운송 건 정보, 입력값, 서명 이미지, 서명 시각, calc_version
- 사용자 입력은 전부 이스케이프

금액·계산 항목은 rules가 null을 주면 PDF에도 "미지원"으로 인쇄한다.
빈칸이나 0으로 두지 마라.

끝나면 실제로 PDF를 생성해서 열고, 한글이 깨지지 않는지 확인해줘.
```

# Phase B — 고시 원문을 구한 뒤 (반나절)

## B1. 원문 대조

`docs/02-RULES-v2026.md`를 열고, 고시 원문과 운영지침을 첨부한 뒤 A절·B절의 모든 `[ ]`를 확정한다. 원문에서 근거를 못 찾은 항목은 **확정으로 표시하지 않는다.**

## B2. 숫자 채우기

```
확정된 docs/02-RULES-v2026.md를 읽고, rules/v2026-02.ts와
rules/v2026-08.ts의 null 반환을 실제 값으로 교체해줘.

- 확정된 항목만 채운다. 미확정 항목은 계속 null로 둔다
- 각 함수 위에 근거 조항과 확인 날짜를 주석으로 남긴다
- 앱 코드는 건드리지 마라. rules 파일만 바꾼다

끝나면
- 손계산과 3건 이상 대조한 결과를 보여줘 (경계값 포함)
- 2026.02 기준 건과 2026.08 기준 건을 각각 만들어,
  과거 건이 당시 버전으로 재계산되는지 확인해줘
```
