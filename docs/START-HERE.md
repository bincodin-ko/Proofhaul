### 2. 미끼 도구 만들기

`03-BUILD-PROMPT.md`의 **명령 0**을 Claude Code에 붙여넣는다. 그대로 복사하면 된다.

만드는 것: 확인서 3종(대기시간 / 험로·오지 / 세척·손상교체)을 입력하고 손가락으로 서명해서 PDF로 내려받는 한 페이지.

**여기서 지킬 것**
- 요율·할증·기준시간 숫자를 **하나도 넣지 않는다.** 아직 원문 대조를 안 했다

- 로그인, DB, 결제 없음
- 입력값은 브라우저 안에서만 처리. 서버로 보내지 않는다

**문구는 부탁이 아니라 제공으로.**
- ❌ "설문 좀 부탁드립니다" / "피드백 주세요"

아무에게도 개인적으로 연락하지 않는다. 전화도, DM도 안 한다.

## 이 프로젝트의 규칙 네 가지

한 번씩 어기고 싶어질 때가 온다. 그때 여기를 본다.

**1. 확인 안 된 숫자를 쓰지 않는다**
`02-RULES-v2026.md`의 B절은 출처를 못 찾은 항목이다. 원문에서 채우기 전까지 코드에 넣지 않는다. 임시로 넣어두는 것도 안 된다. 임시값은 반드시 잊어버린다.

**2. 사람에게 먼저 묻지 않는다**
검증 순서는 ① 이미 쓴 글 읽기 ② 도구 던지고 관찰 ③ 방법 묻기 ④ 중간자 만나기 ⑤ 직접 인터뷰. 위에서부터 쓴다. 낮은 칸으로 답이 나오면 올라가지 않는다.

**3. 범위를 늘리지 않는다**
배차 관리, 대금 정산, 차주용 앱, OCR, 운임 조회 — 전부 안 만든다. 파는 건 **"빠뜨린 증빙이 있다"를 알려주는 것** 하나다.

**4. 중단 기준을 나중에 정하지 않는다**
이미 `00-PLAN.md`에 적혀 있다. 애매해지면 그걸 따른다.

## 아직 모르는 것 세 가지

숨기지 말고 계속 들고 간다.

1. **모집단** — 도달 가능한 운송사가 몇 곳인지 모른다. 공공데이터포털로 센다
2. **정량 고통** — 증빙 없어 포기한 청구가 몇 건인지 모른다. 미끼 도구 사용량으로 간접 확인
3. **셀프서브** — 이 업종이 온라인으로 SaaS를 결제하는지 모른다. 유사 서비스 존재 여부로 확인

셋 중 1번이 가장 위험하다. 모수가 작으면 천장에 막힌다.
