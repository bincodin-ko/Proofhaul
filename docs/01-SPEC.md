# 운임근거함 — 제품 사양

## 한 문장

운송 한 건에 붙는 증빙을 **요청하고 · 받고 · 빠뜨린 걸 찾을 수 있게** 한다.

## 사용자

| 역할 | 로그인 | 하는 일 |
|---|---|---|
| 운송사 사무 담당 | 필요 | 운송 건 등록, 증빙 요청, 누락 확인 |
| 화주 담당자 / 차주 | **없음** | 링크 열어 입력하고 서명 |

서명자에게 회원가입을 시키지 않는다. 가입을 요구하는 순간 서명률이 0에 수렴한다. 이건 편의 문제가 아니라 제품의 성립 조건이다.

---

## 데이터 모델

**모든 `id`는 UUID.** 자동증가 정수를 쓰면 주소창 숫자만 바꿔도 남의 데이터가 열린다.

```
company              운송사
  id, name, biz_no, created_at

user                 운송사 직원 (로그인 대상)
  id, company_id, email, password_hash, name

shipment             운송 건
  id, company_id
  cargo_type          # CONTAINER_20 | CONTAINER_40 | CEMENT | ETC
  origin, destination
  shipped_on          # date
  driver_name, driver_phone
  shipper_name        # 화주
  memo
  created_at

evidence             증빙 1건
  id, shipment_id
  kind                # WAIT | ROUGH_ROAD | WASH_SWAP | RECEIPT | ETC
  status              # REQUESTED | SIGNED | EXPIRED
  token_hash          # 토큰 원문은 저장하지 않는다. 해시만 (05-SECURITY 위협 1)
  requested_at, signed_at, expires_at
  signer_name, signer_role      # SHIPPER | DRIVER
  payload_json        # kind별 입력값
  signature_png_path
  pdf_path
  signer_ip, signer_user_agent  # 분쟁 대비

fee_calc             부대비용 계산 결과
  id, evidence_id
  calc_version        # 예: "2026.08" — 적용 고시/개정 시점
  input_json
  base_amount, surcharge_json, total_amount
  calculated_at
```

### calc_version이 핵심이다

요율은 매년 새 고시로 정해지고 **연중에도 바뀐다.** 2026년만 해도 2월 1일 시행분과 8월 1일 유가 연동분이 다르다.

- 계산할 때마다 그 시점의 규칙 버전을 함께 저장한다
- 과거 건을 다시 열면 **당시 버전으로 재계산**해서 보여준다. 최신 규칙으로 덮어쓰면 안 된다
- 규칙은 `rules/v2026-02.ts`, `rules/v2026-08.ts` 처럼 버전별 파일로 분리한다. 화면·DB에 흩뿌리지 않는다

이 재현 능력이 시간이 갈수록 쌓이는 유일한 자산이다.

## 화면 1 — 운송 건 등록

- 입력: 날짜, 품목, 출발·도착, 차주 이름·연락처, 화주, 메모
- 저장 즉시 증빙 요청 버튼 노출
- **엑셀 붙여넣기로 여러 건 한 번에 등록.** 이 업종은 엑셀에서 온다. 붙여넣기가 안 되면 안 쓴다
- 컬럼 매칭은 첫 줄을 헤더로 추정하고, 사용자가 드롭다운으로 고칠 수 있게

## 화면 2 — 증빙 요청 · 서명

**요청 쪽 (운송사)**
- 증빙 종류 선택 → 링크 생성 → SMS 발송 또는 링크 복사
- 발송 이력과 상태(요청됨/서명됨/만료) 표시

**서명 쪽 (링크를 연 사람)**
- 로그인 없음. 토큰으로 접근
- 모바일 우선. 한 화면에 다 들어가야 한다
- kind별 입력
  - `WAIT`: 도착 시각, 상·하차 시작 시각 입력.
    초과 시간 계산은 **`02-RULES`에서 기산 기준이 확정된 뒤에만** 표시한다.
    확정 전에는 시각만 기록하고 계산란은 "미지원"으로 둔다
  - `ROUGH_ROAD`: 구간 선택 + 사진 첨부
  - `WASH_SWAP`: 체크 + 사진 첨부
  - `RECEIPT`: 수령 확인
- 손가락 서명 캡처 → 저장 시 PDF 생성 → 요청자에게 알림
- 서명 시 IP·UA 기록 (분쟁 대비)

만료는 7일. 만료된 링크는 "만료됨"만 보여주고 재발송을 안내한다.

## 화면 3 — 월별 누락 목록

**제품의 심장.** 재방문 이유는 이 화면 하나뿐이다.

- 이번 달 운송 건 중 **증빙이 없는 건을 맨 위에** 띄운다
- 필터: 상태별, 화주별, 품목별
- 화주별 집계 (누가 자꾸 서명을 안 해주는지 보이게)
- 기간 지정 → PDF 묶음 내려받기 (감사·분쟁 대비)

## 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | Next.js (App Router) | 서명 페이지 SSR — 링크 열림이 빨라야 한다 |
| DB | Postgres (Supabase 또는 Neon) | 초기 무료 티어로 충분. Supabase면 **RLS를 켠다**. Neon이면 테넌트 분리를 앱 레벨 한 곳에서 강제 |
| 파일 | Supabase Storage 또는 S3 | 서명 이미지, 첨부 사진, PDF |
| 인증 | 운송사만 세션 로그인. 서명자는 토큰 | |
| PDF | 서버 렌더 (HTML → PDF) | **한글 폰트 임베드 필수.** 안 하면 깨진다 |
| SMS | 국내 발송 대행 (건당 과금) | 알림톡은 발신프로필 심사 때문에 2주 안엔 무리 |
| 배포 | Vercel 또는 단일 VPS | 월 200달러 안 |

### 예산 방어

- 고객 100명 기준 월 원가를 Day 12에 계산한다
- SMS가 가장 위험하다. 건당 단가 × 예상 발송량이 객단가의 30%를 넘으면 링크 복사 우선 + SMS는 선택 기능으로 내린다

## 보안

전체 기준은 `05-SECURITY.md`. 이 제품은 **로그인 없이 열리는 링크**가 핵심 기능이라 공격 표면이 거기 몰려 있다. 화면 2를 만들기 전에 반드시 통독한다.

## 개인정보

이 서비스는 **타인의** 이름·연락처·서명 이미지·접속 IP를 저장한다. 내 회사 데이터가 아니다.

- 서명 화면에 수집 항목·목적·보관 기간을 고지하고 동의를 받는다
- 개인정보처리방침 페이지를 둔다
- 보관 기간을 정하고, 지난 데이터를 지우는 스크립트를 만든다
- 서명 이미지·첨부 사진은 URL만 알면 열리지 않게 한다 (서명된 URL 또는 권한 검사)
- 로그에 연락처·서명 데이터가 남지 않게 한다

분쟁 대비가 목적이라 보관 기간을 길게 잡고 싶어지는데, 길수록 사고 시 피해가 커진다. 기간은 근거를 정하고 명시한다.
